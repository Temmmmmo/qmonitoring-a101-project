# Привязка по исходному DXF и сохранённым мешам Revit — 10 сентября 2026

На реальном отчёте `revit_info/051/qmonitoring-cad-20260910-095834-615000.json`
получен **`source_snapshot_matches`**. Это новый, явно выбранный путь проверки
снимка координат; он не переименовывает неизвестные CAD-слои и не разрешает размещение.
Повтор того же CAD Probe 0.5.1 сейчас не требуется. Архив/кнопки pyRevit не изменены.

## Что доказано на полученных данных

  длина 3900 мм, фактический шаг 96,875 мм, между крайними осями 775 мм.
- CAD Probe: связь 407861 загружена; `IsModified=false` до и после. Файл связи
  1 443 515 байт совпадает с предоставленным верхним X DXF по SHA256.
- Два способа API-чтения дали одинаковое мультимножество 8450 треугольников,
  несмотря на другой порядок мешей и объектов. Повторения учитываются, не удаляются.
- Все **2132 КЭ и 2209 вершин** исходного `KLEENKA` сопоставлены. Каждый КЭ встречается
  ровно два раза. Максимальная ошибка вершины — **0,0012847201 мм**, допуск 0,1 мм.
  Ни масштаб, ни перенос не подбирались: проверена записанная единичная матрица.
- Требования берутся из DXF + явно выбранного SHK: уровни содержат 791 / 788 / 388 /
  165 КЭ, все добавки сохранены. Геометрические копии **не удваивают спрос**.

Исходный CAD Probe остаётся `partial`: пять мешей имеют `GraphicsStyleId=-1`, слои
не определены. Два `Solid` с нулём граней дали сообщения `Empty CAD solid`, из-за
чего исходный сравнитель не запускался. Каталог наличия `KLEENKA` не доказывает
принадлежность ему конкретного меша. Цвета CAD-кэша также не подтверждены.

## Новый явный контракт

`application/revit_source_binding.py::verify_source_binding`, формат
`revit-source-binding/v1`, обязательный профиль
`linked-dxf-authority/mesh-snapshot-v1`.

Источник требований — **выбранные внешние DXF и SHK**, не цвет/материал меша в RVT.
Обычный ingest читает только `KLEENKA`, сохраняет шкалу и нормализует единицы.
Отчёт содержит SHA256 DXF, SHK и оригинального JSON, направление, полную шкалу с
составами, количество КЭ по уровням, записанную матрицу, ID/UniqueId связи и host.
Это кандидат привязки к снимку документа, не проверка актуальной открытой модели.

Число ожидаемых геометрических копий **обязательно задаётся явно**, допустимы 1 или 2.
Для `051` нужно 2; это не число слоёв арматуры и не назначение имён `KLEENKA`/`PLAST`.
Каждый КЭ должен быть представлен ровно этим числом полных триангуляций. Две копии
квада могут иметь разные допустимые диагонали; смешанные/неполные триангуляции,
недостающие и лишние треугольники блокируются. Нельзя выбрать только удобный меш.

Численная часть вынесена в общий внутренний `_compare_triangles` существующего
DXF-checker: два пути используют одну проверку вершин, владения треугольниками,
контрольных точек и размеров. Старый `verify_dxf_calibration` по-прежнему требует
подтверждённого CAD-слоя и полного отчёта. Автоматического переключения нет.

### Границы поддержанного снимка

- Только исходный read-only CAD Probe **0.5.1**, загруженная **связь**, точный хеш DXF,
  неизменившийся и известный флаг модификации документа. Импорт без fingerprint не подходит.
- Единицы мм; одно плоское исходное поле; записанное жёсткое горизонтальное
  преобразование без масштаба, отражения, наклона или сдвига по подгонке.
- Проверяются все сохранённые прямые Mesh, их declared/actual counts, ссылки на
  trusted payload, уникальность путей, инвентарь объектов, счётчики ошибок и лимиты.
  Сложные Solid/Face-представления пока вне этого узкого профиля.
- Из неполного чтения распознаются только конкретные диагностические случаи 0.5.1:
  неизвестные слои и `Empty CAD solid`, причём сообщение должно соответствовать
  записанному объекту Solid. Они сохраняются как ограничения полного CAD-чтения.
  Иные ошибки, пропущенные меши/инвентарь, лимиты и необъяснённый `partial` блокируют результат.
- Два API-снимка здесь должны **точно** совпасть как мультимножества координат
  треугольников. Порядок вершин/мешей не важен; даже малое расхождение между способами
  чтения блокируется. Это строже старого API-сравнителя с допуском 0,01 мм.
- Поиск соответствий исходным вершинам ограничен 1 000 000 проверок кандидатов;
  20 000 треугольников и 5000 объектов на API-снимок. Превышение не считается частичным успехом.

Всегда `placement_eligible=false`, `live_binding_verified=false`,
`cad_layer_identity_verified=false`, `cached_cad_colours_verified=false`,
`complete_cad_geometry_verified=false`. Исходные `partial`, issues и comparison
сохраняются отдельно. Требуется инженерное подтверждение выбранной шкалы/фаз/укладки.
Z мозаики −8970 мм проверяется только как координата CAD; Z арматуры задаётся от граней плиты.

## Воспроизведение

```bash
python3 scripts/verify_revit_source_binding.py \
  --dxf 'Дополнительные материалы/Изополя(мозаики) армирования/2 фона/Верхнее армирование вдоль ОСИ Х.dxf' \
  --shk 'Дополнительные материалы/Изополя(мозаики) армирования/2 фона/К09_фп_2 фона_Вх.shk' \
  --report revit_info/051/qmonitoring-cad-20260910-095834-615000.json \
  --policy linked-dxf-authority/mesh-snapshot-v1 \
  --expected-mosaic-copies 2 \
  --output /tmp/new-source-binding.json
```

Выходной путь должен быть **новым** `.json`; без `--output` результат идёт в stdout.
CLI ограничивает DXF 64 MiB, SHK 1 MiB и JSON 32 MiB, отклоняет повторные ключи,
NaN/Infinity и неверную корневую структуру. Хеши всех трёх входов проверяются до/после.
Exit 0 — совпал снимок, 1 — проверка заблокирована, 2 — ошибка входа/файла.
Ни один exit code не разрешает применение в Revit.

Сохранены локальные артефакты в `artifacts/revit_source_binding_2026_09_10/`:

| Файл | Результат |
|---|---|
| `source-binding.json` | `source_snapshot_matches`, 2132 КЭ, 8450 треугольников, все вершины совпали |
| `wrong-multiplicity.json` | `blocked`: при ошибочно заданной одной копии не проходит ни один из 2132 КЭ |
| `strict-calibration.json` | прежний checker остаётся `blocked`, статус исходника не подменён |

## Что это меняет для следующего этапа

Теперь есть воспроизводимая offline-проверка, на которую можно опереться при подготовке
результата по исходному DXF. Повторять диагностику ради того же `GraphicsStyleId` не нужно.
Следом нужны составной поиск и проверка осей относительно host/cover/проёмов,
утверждённые фазы и порядок X/Y, актуализация связи/документа перед операцией,
trial реальных зон, применение и выноски. Ни этот отчёт, ни Reference Probe не закрывают
полный гейт 8 или остальные недостающие части [матрицы 8/8](delivery-readiness-2026-09-09.md).

Специалисту можно ответить:

> Спасибо, оба отчёта проверил. Геометрия из модели совпала с исходным DXF по всем
> вершинам; ошибки масштаба или переноса в считанной мозаике не нашёл. Повторять 0.5.1
> не нужно. Слои Revit не отдал, поэтому для расчёта буду читать их из исходного DXF,
> а привязку проверять по геометрии модели. Следующий пакет подготовлю для проверки
> реальных зон. Пока ничего дополнительно запускать или менять в модели не нужно.
