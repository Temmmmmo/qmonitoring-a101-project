# Несколько раскладок К09 и готовых инженерных примеров

## Пользовательский сценарий

На `/composite?example=k09-typical-3-14` нажать «Рассчитать плиту», затем выбрать
«Вариант раскладки» над метриками. Если оригиналы К09 установлены, он становится
готовым примером по умолчанию; при их отсутствии остаётся С1. Синтетической
подмены или выдачи сохранённого удачного расчёта нет.

Переключение меняет весь отчёт: четыре физические схемы, исходные изополя и зоны,
позиции, массу, проверки, JSON для Plan Preview и JSON выбранной партии для Review.
Проверки одного варианта не относятся к другому. Старый обычный составной сценарий
со своим фронтом сохраняется; переключение между расчётами сбрасывает состояние.

## Поиск и проверка

- Один GA-прогон возвращает полный исходный фронт, а не запускается заново для
  каждого пункта списка. Исходные лимиты, сохранение одиночных КЭ и hard-validation
  не ослаблены.
- Из него сохраняется исходный кандидат минимальной массы и до четырёх альтернатив
  из конечного фронта с разным числом стержней. Это бюджет исходных кандидатов,
  не обещание пяти физических решений.
- Каждая исходная раскладка независимо проходит схемы осей, физическую обработку,
  ограничение внешнего контура и повторные проверки. Геометрические дубликаты
  после обработки исключаются; поиск следующего варианта продолжается до трёх
  разных партий либо исчерпания переданных исходных кандидатов.
- Отказ отдельного кандидата сохраняется в `variant_rejections` и не уничтожает
  готовые соседние варианты. Если нет полной физической партии ни у одного,
  возвращается ошибка, а не промежуточная выдача под видом результата.
- Названия «Меньше массы / стержней / позиций» сравнивают конечные показанные
  варианты. Это не глобальные оптимумы и не инженерно заверенные решения.

## Внешний контур К09

Обычный готовый К09 теперь использует внешний контур объединения оригинальной
КЭ-сетки четырёх DXF. Корректируются реальные стержни и экспорт, а не SVG-картинка.
После ограничений применяется существующий bounded repair; исходные КЭ не удаляются.
Вариант с ненулевым выходом тела за этот контур не выдаётся.

Модель явно плоская, 200 мм, без отверстий и защитного слоя. И успешная физическая
нормализация, и ветка неподтверждённого исходного раскроя используют один
`ResearchLayerProfile`: X ближе к граням, Y со смещением осей 16 мм. Это условная
политика проверки, не автоматическое подтверждение настоящей высоты Revit.
При неподтверждённом исходном раскрое полная исходная геометрия обрабатывается
самостоятельно; `physical_normalization_completed=false`, исходный статус раскроя
и новые проверки не переименовываются в успех.

DXF-контур не выдается за native Floor. Для известной рабочей плиты К09 можно
раскрыть пересчёт по Working Host, загрузить актуальный снимок и подтвердить XY.
Этот web-маршрут теперь использует оба native-внешних контура плиты 200 мм,
без отверстий и cover, через существующий dual-exterior repair. При создании
Review дополнительно проверяет текущую геометрию Floor. Сам web-прогон RVT не меняет.

## Первый контрольный прогон реальных четырёх DXF

`artifacts/engineering_variants_2026_09_16/summary.json`, 195,26 с. Три партии имеют
разные SHA256 физических координат, диаметров и материала, а не разные названия.

| Вариант | Масса, кг | Стержни | Позиции | Вне DXF | Непокрытые КЭ | КЭ без 40d |
|---|---:|---:|---:|---:|---:|---:|
| Меньше массы | 2849,18 | 949 | 124 | 0 | 3 | 179 |
| Меньше позиций | 4361,67 | 970 | 113 | 0 | 3 | 180 |
| Меньше стержней | 3168,24 | 868 | 126 | 0 | 5 | 179 |

Безотходный раскрой после изменения длин не пройден во всех трёх. Первый и второй
варианты сохраняют 3 геометрических остаточных КЭ, третий — 5; экономическое
сравнение не является доказательством инженерной эквивалентности. В частности,
вариант с меньшим числом позиций намного тяжелее — он не объявляется победителем.
Все эти статусы доступны для выбранной партии. Геометрия Revit в этом прогоне
не считывалась. Готовность инженерного выпуска остаётся false.

Повторный прогон окончательного кода сохраняется отдельно в
`artifacts/engineering_variants_2026_09_16/latest-v2/`.
Он завершился за 194,69 с и воспроизвёл все три партии и их численные проверки.
Из бюджета пяти исходных кандидатов достаточно первых трёх; `variant_rejections=[]`.
Вторая партия в этом прогоне использовала ветку неподтверждённого исходного
раскроя, сохранив ту же геометрию и единый профиль смещения Y 16 мм.
Все три выбранных JSON прошли `qm_rebar_review.validated_graphics` плагина 0.1.6
с полными количествами 949/970/868. Это проверка транспорта, не создание в Revit.

## Проверка кода

Новые тесты проверяют единичный GA-прогон, отдельную provenance кандидатов,
различие геометрий, backfill после дубликатов и отказов, запрет выдачи неполной
партии, ограничение настоящих осей по внешнему контуру, смену схемы/статусов/JSON
на сайте и сброс состояния при следующем обычном расчёте. Не являются тестами
живого Revit. Плагин 0.1.6 не менялся; новый web-экспорт использует уже поддержанные
схемы `graphic-bar-plan-draft/v1` / `graphic-bar-plan-repaired/v1`.

148 профильных тестов прошли, полный Ruff по `src tests scripts integrations/pyrevit`,
`node --check` и `git diff --check` прошли. Полный pytest всего репозитория
локально в этой итерации не запускался; его выполняет CI.
CI коммита `076a8ee` завершился: 3858 passed, 63 skipped, Docker build и Deploy успешны.

## Упрощение сайта после обратной связи

Основной путь — готовая плита, расчёт, варианты, JSON для Revit. Для готового
примера не нужны ручные фазы. На странице есть краткое объяснение фона/добавок
и трёх разных показателей. Для своего проекта привязка разъяснена примером
0/300/600 → 100/400/700; настройки поиска и раскроя раскрываются отдельно.
Не заявляется считывание существующего фона или проверка всех его пересечений.

Ошибка показывает понятное действие по категории (сервер, шкала, привязка, контур,
покрытие, формат); исходный текст сохранён в отдельном раскрытии через textContent.
Реальные fail/not_checked и ограничения не скрыты. Страница Revit сначала предлагает
создание Rebar и просмотр изополей/зон; остальные работающие диагностические
инструменты и технические вычисления глубин вынесены в раскрываемые блоки.
Объяснено автоматическое предложение высот, без необходимости ручного ввода.

96 web-тестов и полный Ruff прошли, оба JS прошли node --check, diff --check чистый.
Независимый Sol-review блокирующих замечаний не выявил. Браузерное визуальное QA
пытались выполнить, но CUA сообщил «No browser is available»; скриншот не проверен.
Алгоритмические геометрии трёх вариантов этими текстовыми/UI-правками не изменены.

Команда реального прогона: `PYTHONPATH=src python scripts/verify_engineering_variants.py`.
Оригиналы подключаются через `REBAR_ENGINEERING_INPUTS_DIR`, не входят в Git;
артефакты также не коммитятся. Несколько вариантов добавлены и в готовый С1,
но отдельный полный реальный прогон С1 в этой итерации не выполнен.
