# Сообщение для тестового создания в pyRevit

Отправить вместе с `qmonitoring-revit-probe-0.2.1.zip` из `artifacts/revit_probe/`.
Сам ZIP содержит только код и инструкцию; модель и DXF повторно пересылать не нужно.

---

Спасибо, оба отчёта получил. Чтение эталона прошло полностью, теперь и проверка шага
сходится. Второй тест остановился ещё до создания: моя проверка места поймала эскиз
и объект с именем «{3D}». Ничего в модели не создавалось.

Уточнил проверку: служебные объекты распознаются по данным Revit; реальные препятствия
по-прежнему блокируют запуск. Если назначение объекта не удастся подтвердить, скрипт
остановится и запишет подробности. Ничего удалять, скрывать или двигать не нужно.

Прикладываю архив 0.2.1. Закрой Revit и замени QMonitoring.extension в той же
подключённой папке. После перезапуска открой ту же тестовую копию модели и нажми
QMonitoring → Diagnostics → Creation Trial. Путь в настройках менять не нужно.
Reference Probe повторять не нужно. В журнале должна быть версия 0.2.1.

Пришли новый JSON и скриншот окна результата pyRevit. Тест по-прежнему создаёт один
набор временно и обязательно отменяет создание, даже при успехе. Если появится ошибка,
пришли полный журнал с первой строкой версии. Если скрипт не подтвердит откат,
закрой тестовую копию без сохранения.

---

Разработчику: команда сборки — `python3 scripts/package_revit_probe.py`.
Полная инструкция и границы проверки: [`../integrations/pyrevit/README.md`](../integrations/pyrevit/README.md).
Ожидаемый статус нового теста — `passed_rolled_back`. Это совпадение геометрии до
Commit и проверенный откат, не инженерная приёмка. В 0.2.0 создание не начиналось.
Назначение общего Element `{3D}` в старом JSON не доказано: его категорию проверит 0.2.1.
Фазы фоновых/дополнительных наборов и порядок X/Y этим запуском не согласовываются.
