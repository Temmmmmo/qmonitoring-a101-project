# Новый объём по ТЗ: целый сдвиг внутрь, без отверстий и защитного слоя

15.09.2026. Реальная плита К09 над 3-м этажом, `plate:52`.

## Результат за минуту

**Старые 289 — больше не число отказов в выбранном пользователем объёме задачи.**
После исключения отверстий и защитного слоя остаётся **159 выходов за внешний контур**.
При сдвиге с сохранением всей исходной потребности исправлены 14: осталось **145**.
Непокрытых исходных КЭ — **0**; отдельно остаются **11 пар коллизий**.

Это не упавшие программные тесты. Это нарушения проверяемой раскладки. Тесты, в том
числе, проверяют, что программа обнаруживает такие нарушения и не выдаёт их за успех.

**Геометрическая идея пользователя работает:** буквальное перемещение целых стержней
оставляет всего 12 выходов при продольном сдвиге, либо 11 при сдвиге по двум осям.
Но эти два варианта не приняты: по сохранённой модели 40d теряют покрытие 136/157 КЭ
и дают 55 пар коллизий. Нельзя предъявлять «осталось 11» без этих двух последствий.

## 1. Что изменено по прямому указанию пользователя

Новая явная политика: `user-TZ-outer-boundary-no-openings-no-cover/2026-09-15-v1`.

- Замкнутые отверстия исключены из расчётной области препятствий. Исходные КЭ,
  включая их потребность, при этом не вырезаны и не изменены.
- Защитные слои 40/40/25 мм исключены из критериев отказа по выбранному объёму ТЗ.
  Измеренный Revit snapshot не переписан; его параметры показаны только отдельно.
- Внешний контур сохранён, включая его вогнутые участки и разные сечения по высоте.
  Замены плиты ограничивающим прямоугольником или выпуклой оболочкой нет.
- Проверяется полное тело стержня, а не только две конечные точки. Диаметр сохраняется.
- Стержень переносится целиком: длина, диаметр, материал, форма, высота и ID не меняются.
  Новые загибы, обрезка и удаление «неудобных» стержней в этой серии не применялись.
- Проверки исходной потребности, оставшейся модели 40d, взаимных 3D-коллизий,
  осей заданного фонового армирования и раскроя 11700 мм сохранены.

Это реализация договорённости «расположить зону несимметрично относительно пятна
потребности — сместить её внутрь плиты». Продольное положение выбирается сначала
по внешнему контуру **без предварительного отсева по 40d**. После этого отдельная
проверка сообщает, проходит ли предложенное положение остальные условия.

Код:

- [проверки и область нового объёма](../src/rebar/optimization/services/tz_outer_scope.py);
- [генератор целых сдвигов](../src/rebar/optimization/algorithms/tz_outer_repair.py);
- [воспроизводимый запуск на исходных данных](../scripts/experiment_tz_outer_scope.py);
- [регрессионные проверки](../tests/optimization/test_tz_outer_scope.py).

Реальная Revit-проверка оставлена отдельным информационным результатом. Её `blocked_host`
не переносится в статус по ТЗ. Обратное тоже верно: прохождение ограниченного объёма
задачи не доказывает, что сталь помещается в настоящем бетоне с отверстиями и cover.
Этот новый сценарий пока запускается через CLI; web/production и Revit-пакет им не заменены.

с 139 исходными параметрическими зонами либо 902 физическими стержнями.

## 3. Сколько осталось и почему

**145 внешних нарушений**: bottom-X — 8, bottom-Y — 32, top-X — 54, top-Y — 51.
Это геометрический факт именно проверенного кандидата, не нехватка данных о cover.

| Группа среди этих 145 | Стержней | Что установлено |
| --- | ---: | --- |
| Найдены положения целиком внутри, но проверенные сдвиги теряют FE-покрытие с 40d | 134 | Такие предложения отвергнуты; прежние стержни остались с явной ошибкой края |
| Полная длина не помещается в доступном диапазоне поперечных осей | 11 | Проверены геометрические критические положения; ограничение относится к фиксированной длине и текущим окнам поиска |

Группы 134/11 не пересекаются. **Это причины неуспеха данного ремонта**, а не доказательство
того, что правильная инженерная раскладка вообще невозможна.

Отдельно **11 подтверждённых пар коллизий** затрагивают **22 стержня**. Два из этих
стержней уже входят в 145 внешних нарушений; ещё 20 находятся внутри внешнего контура.
Итого **165 различных стержней** затронуты хотя бы одним из двух оставшихся
геометрических условий. Складывать `145 + 11` как число стержней неправильно.
Коллизий с неопределённым результатом проверки — 0. Минимальный проверенный зазор до
предписанных исходником осей фоновой сетки — 0 мм (касание, не проникновение).

**Что не является причиной этих 145:** отверстия, 40/40/25 cover, таймаут,
отсутствие нового Revit JSON. Последний нужен для подтверждения интеграции, а не для
объяснения локального выхода за уже прочитанный внешний контур.

**Что остаётся ограничением модели/недоказанным:** восстановленные конечные окна
обслуживания исходных зон, сохранение длины за каждым ID, одиночный порядок ремонта,
полный прямой участок 40d с каждого конца, исследовательская укладка по высоте,
неподтверждённая несущая способность ранее построенных U-узлов. Сертификат новых
прямоугольных зон и фаз СТО после физических перемещений не заявлен. Эти пункты
нельзя считать автоматически решёнными оттого, что отверстия и cover исключены.

## 4. Примеры, на которых можно обсуждать решение

### А. Сдвиг действительно помог

`bottom-X / source-recovery-6/0/2`, Ø10, длина 1300 мм, Y=13700, Z=6955:
прежние концы X=1362,1235…2662,1235 перемещены в **1400…2700**, целиком на **37,8765 мм**.
Длина не уменьшилась. В проверке всей партии исходная потребность не потеряна,
новых коллизий нет. Это один из 14 принятых сдвигов.

### Б. Геометрия проходит, но расходится с текущим правилом 40d

`bottom-X / genetic-4/0/10`, Ø10, длина **4875 мм**, Y=13600, Z=6955:

| Величина | Значение, мм |
| --- | ---: |
| Прежние концы X | 17831,504…22706,504 |
| Внешний край плиты | 22200 |
| Буквальный целый сдвиг внутрь | −506,504 |
| Концы после сдвига | 17325…22200 |
| Правый предел обслуживаемого участка при оставшихся 40d | 22200 − 400 = 21800 |
| Правый край ещё необходимого участка исходного КЭ 244 | 22200,001 |

Оба конца и всё тело после сдвига **внутри внешней границы**. Никакой проверки cover
или отверстия здесь нет. Но при неизменных соседях требование на торец получается
одновременно `end ≤ 22200` и `end ≥ 22200,001 + 400 = 22600,001`.
Расхождение **400,001 мм**, не 25 мм cover и не одна лишь численная погрешность.

Отдельная проба на последнем кандидате теряет части КЭ **244, 249, 320, 825**,
суммарно **63 317,311691 мм²** в принятой модели обслуживаемых полос.
Это результат проверяющей модели покрытия, **не отдельный расчёт прочности**.
См. `single_whole_shift_examples[0]` в JSON диагностики.

Второй пример: `top-X / genetic-19/0/9`, Ø10, L=1950, Y=13600, Z=7065.
Сдвиг X=8702,8105…10652,8105 → **8230…10180** помещает стержень в плиту,
но теряет части КЭ **908 и 1048**, всего **93000 мм²**; рабочий конец по 40d — X=9780,
тогда как остающаяся потребность доходит до X=10090.

**Откуда 40d:** в исходном [ТЗ](../Техническое_задание_А101_ТЗ_Техлаб_2026.pdf)
PDF-страница 7 — «удлинение ЗА границу мозаики на длину >=40d», рисунок с выпусками
по концам; страница 11 — примеры Ø25→1000 мм и Ø20→800 мм; страница 14, п. 7 —
настраиваемое правило удлинения с указанным значением по умолчанию.
[Запись встречи](../Встреча_с_разработчиками_сервиса_по_ИИ_армирования_Вопросы_и_ответы.txt),
00:05:22, отдельно уточняет: «40 туда, 40 туда», а не 10/70 или 30/50.

**Где расходятся постановки:** пользователь просит оставить стержень целиком внутри.
Сдвиг выполняет это, но не гарантирует старый выпуск с обеих сторон пятна потребности.
ТЗ содержит 40d, однако наша универсальная модель `отрезок минус 40d с двух концов`,
фиксированные окна и неизменная длина каждого ID — не дословно заданный заказчиком
алгоритм для каждого краевого узла. Ни молча отменять 40d, ни объявлять невозможной
любую инженерную раскладку на основании этого примера нельзя.

### В. Стержень длиннее доступного прямого участка

`bottom-Y / source-recovery-1/0/0`, Ø10, L=**11700**, X=13600, Z=6971.
Исходные Y=−456,3435…11243,6565. При X в текущем окне **13600…13900** максимальный
непрерывный участок внешней плиты — **9540 мм**. Не хватает **2160 мм**.
Это внешний вырез контура, не замкнутое отверстие и не защитный слой.

Для 11 случаев геометрически проверены все критические поперечные положения и
интервалы между ними для ортогонального телесного контура. Дефициты длины:
**4 × 2160 мм, 5 × 280 мм, 1 × 180 мм, 1 × 210 мм**.
Фиксированные окна происхождения и предел ±300 мм — ограничение текущего ремонта,
не утверждение, что ТЗ запрещает строить другие зоны. Новую длину можно выбирать
при совместном перерасчёте, но в этой серии длину существующего стержня не меняли.

### Г. Коллизия внутри контура — отдельная проблема

`top-X / pairwise-12`, Ø12, X=8053,5715…13903,5715,
и `top-X / pairwise-2`, Ø12, X=12131,378143…21881,378143.
У обоих Y=1900, Z=7064. Оси совпадают на **1772,193357 мм** длины;
межосевое расстояние 0 при сумме радиусов 12 мм. Это реальное наложение тел,
не допустимое ортогональное X/Y-пересечение.

Ещё пример: `top-X / genetic-24/0/8` Ø10 и `pairwise-26` Ø12, у обоих Y=2500,
но Z=7065/7064. Межосевое расстояние по высоте **1 мм**, сумма радиусов **11 мм**.
Простого наличия разных Z недостаточно. В v2 проверены и эти одиночные перестановки:
65 предложений после проверки покрытия отклонены из-за конфликта тел.

## 5. Следующие короткие проверки и предметный поиск методов

1. **Для 134 случаев — совместная перестройка малой группы.** Сначала взять пример Б
   и его соседей, пересобирать всю группу с неизменными исходными КЭ, затем проверять
   полное покрытие, контур, пары и раскрой. В статье Li et al., IJCAI 2021 применяется
   Large Neighborhood Search: выбирается подгруппа, остальные решения фиксируются,
   подгруппа перепланируется вместе. Для нас это гипотеза переноса метода на статическую
   арматуру, не готовый инженерный алгоритм. Она различит недостаток одиночного ремонта
   и конфликт самой прямой 40d-модели. [Первичная статья](https://www.ijcai.org/proceedings/2021/0568.pdf).

2. **Для 11 слишком длинных — выбирать длины после геометрической допустимости.**
   Не обрезать уже выбранный стержень; пересобирать набор длин группы/раскрой партии,
   сохраняя всю потребность. Геометрическую область допустимых переносов строить заранее.
   Это соответствует конфигурационному пространству: сумма Минковского объекта и
   препятствий описывает запрещённые положения. В этой серии уже вычислены допустимые
   продольные интервалы целого тела, без дыр/cover. Библиотека CGAL не подключалась;
   её документация подтверждает математический подход, не армирование. Для контура
   нашей плиты достаточно ортогональных операций, общий 3D алгоритм избыточен.
   [CGAL: первичная документация](https://doc.cgal.org/latest/Minkowski_sum_3/index.html).

3. **Для 11 пар — локально перепланировать сразу оба участника и соседей.**
   Нельзя засчитывать тонкий визуальный разнос как отсутствие пересечения тел.
   Нужен конечный каталог совместных положений и независимая полная FE/3D-проверка.
   Если каталог неразрешим, извлечь конфликтующие ограничения, а не сообщать общий
   «не удалось». SCIP описывает IIS — неразрешимую подсистему ограничений; её можно
   использовать для объяснения конфликта конечной модели. Это не разрешение удалить
   инженерные условия и не доказательство невозможности вне данного каталога.
   [SCIP: описание IIS](https://scipopt.org/doc/html/iisfinder__greedy_8h.php).

Предыдущие совместные v5/поиски форм использовали другой объём с отверстиями/cover;
их численные остатки не переносятся на новую задачу. Новый совместный поиск групп
под новой политикой ещё не выполнен. Увеличение поколений старого GA само по себе
не устранит показанное противоречие `end≤22200` / `end≥22600,001`.
