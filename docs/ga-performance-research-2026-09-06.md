# Следующая итерация: время детализации и распределение бюджета поиска

Продолжение [H6–H7](ga-hybrid-research-2026-09-06.md), 6 сентября 2026.
Новый выигрыш ниже относится к вычислениям; снижение массы предыдущей серии не
пересчитывается и не выдаётся за повторное улучшение этой итерации.

## H8: меньше лишних геометрических проверок

Гипотеза: перебор всех КЭ для каждой зоны расходует время на заведомо удалённые
полигоны. Построен консервативный индекс `services/spatial_index.py` по bbox КЭ.
Он выбирает кандидатов, но площадь всё равно вычисляется точным пересечением полигона
с прямоугольником. Исходный порядок КЭ сохраняется. Граничные координаты расширяются
на общий геометрический допуск; крупные полигоны/запросы используют полный просмотр.

Индекс хранится в `DetailingContext`, не в публичном `models.py`. Независимый
hard-валидатор индекс не использует. Отдельный тест намеренно ломает индекс:
проверка обнаруживает некорректный кэш покрытия и отклоняет результат.

Также убран повторный сбор покрытия в GA: до подбора фаз строится геометрия без
кэша, после подбора фаз кэш собирается один раз. Если подбор фаз завершился ошибкой,
полное покрытие исходных зон восстанавливается; диагностическая ветка не упрощена.
Обе ветки сравниваются с прежней материализацией в тестах.

### Последовательный A/B

Плита нуля, четыре направления, seed 7, uniform, p8/g3, physical_bar_count,
recombination=1500, local=4. **MILP выключен**, общий deadline отсутствует, чтобы
изменение скорости не меняло количество исследованных вариантов. Ingest и запись
отчёта находятся вне таймера; подготовка пула и итоговая hard-validation входят.

На каждом направлении два повтора: контроль → индекс, затем индекс → контроль.
Наши тяжёлые тесты и другие эксперименты одновременно не запускались. Это измерение
на локальном компьютере, не изолированный сервер и не гарантированный SLA.

| Направление | Полный просмотр, с | Индекс, с | Сокращение времени |
|---|---:|---:|---:|
| Нижнее X | 38,23 | 31,73 | 17,00% |
| Нижнее Y | 26,08 | 22,30 | 14,49% |
| Верхнее X | 60,68 | 51,20 | 15,63% |
| Верхнее Y | 39,99 | 32,33 | 19,17% |
| Сумма средних | 164,98 | 137,55 | 16,63% |

В таблице среднее двух повторов; всего 16 направленных запусков. Для каждой пары
совпадает SHA-256 полного результата: зоны, физические метрики, статус и диагностика.
Временная телеметрия в fingerprint намеренно не включена. Найденные точки фронта
не изменились. Верхнее X заметно менялось по времени между повторами, поэтому
не делаем статистических выводов по двум измерениям.

Устранение двойного сбора покрытия включено **в обеих ветках** этого A/B: цифры
изолируют эффект индекса, а не совокупный выигрыш против исторического H7.
Базовые формулы, 40d, ширина, As, mapping, стандарты и правила фаз не изменены.

Воспроизведение:

```bash
python3 scripts/profile_detailing.py <четыре-DXF-плиты-нуля> \
  --repeats 2 --out-dir artifacts/ga_h8_detail_index
```

Исходные замеры: `artifacts/ga_h8_detail_index/profile.json`.
Индекс включён в общий конструктор как ускорение с неизменным физическим результатом;
подмена индекса полным просмотром доступна в исследовательском скрипте.

## H9: порядок промежуточных MILP

Гипотеза: при общем лимите 10 секунд сложный промежуточный бюджет числа стержней
может поглотить оставшееся время. Проверяется обратный порядок тех же бюджетов:
сначала ближе к minimum mass, а не к minimum complexity. Первые три задачи,
пул, ограничения и максимум шесть вызовов одинаковы. На каждый вызов теперь
записываются выделенное оставшееся время и фактический runtime.

`budget_order` — внутренний исследовательский параметр `polish_candidate_pool`;
GA/web/benchmark defaults не переключены. Порядок `complexity-first` остаётся контролем.
Статус и gap имеют смысл только для конечной модели атомов. Согласно
[документации SciPy MILP](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.milp.html),
остановка по лимиту не гарантирует оптимального решения; отсутствие integer incumbent
нельзя интерпретировать как отсутствие допустимой раскладки.

Парный скрипт `scripts/research_pool_schedule.py` строит пул один раз на направление,
сохраняет его fingerprint, чередует порядок A/B и материализует каждое предложение
общим конструктором с независимой hard-проверкой. К обеим сериям добавляются одинаковые
baseline-родители. Hypervolume использует общие границы внутри пары.
Это **изолированный pool polish**, не новый полнокомплектный GA benchmark:
он не позволяет заявлять выигрыш полного алгоритма или глобального Парето-фронта.

```bash
python3 scripts/research_pool_schedule.py <четыре-DXF-плиты-нуля> \
  --repeats 2 --time-limit 10 --out-dir artifacts/ga_h9_schedule_plate_zero
```

### Результат H9: основной порядок не меняем

Плита нуля, seed 7, четыре направления, два повтора с обратным порядком A/B:
16 запусков pool polish, 80 MILP-вызовов. Проверены 74 integer-предложения и 12
общих baseline-родителей; hard-rejections — ноль. Для каждой пары используется
один и тот же пул с совпадающим SHA-256. Минимальная масса совпала во всех парах.

| Направление | Изменение HV, mass-first минус контроль | Наблюдение |
|---|---:|---|
| Нижнее X | −0,05510 в обоих повторах | Обратный порядок хуже охватывает компромиссы |
| Нижнее Y | 0 в обоих повторах | Все шесть задач успели завершиться, порядок не повлиял |
| Верхнее X | −0,01353; 0 | До изменённой части расписания вообще не дошли |
| Верхнее Y | 0 в обоих повторах | Все шесть задач завершились, порядок не повлиял |

Верхнее X — важный контроль интерпретации: третья, одинаковая для A/B задача
«масса при минимуме стержней» забрала остаток лимита. Различие первого повтора
относится к найденному incumbent при wall-clock cutoff, **не к порядку бюджетов**.
На нижнем X на пятом вызове исчерпан лимит, шестой бюджет не исследован. Просто
развернуть очередь недостаточно; больше предложений также не гарантирует больший HV.

Решение: `complexity-first` остаётся основным. Альтернатива сохранена только как
воспроизводимый внутренний исследовательский контроль. Следующая содержательная
гипотеза — резервировать время для промежуточных точек, ограничив третью задачу,
а не увеличивать общий лимит. Она **ещё не реализована и не проверена**.

Полные статусы, gap, выделенные лимиты, времена и hard-valid точки:
`artifacts/ga_h9_schedule_plate_zero/schedule.json`.

## Автоматические проверки

Целевая серия новых/расширенных тестов: **85 passed**. Она включает 14 малых задач
× две оси сложности × оба порядка MILP с независимым полным перебором; сравнение
индекса с полным просмотром на треугольниках и границах; совпадение детализации X/Y;
отбраковку повреждённого кэша; обе ветки материализации при подборе фаз.

Полный прогон в окружении с optional SciPy: **324 passed** за 140,71 секунды.
Та же целевая серия в базовом окружении без SciPy: **23 passed, 62 skipped**;
solver-проверки явно пропускаются, базовая детализация работает без новой зависимости.
`ruff check src tests scripts`, `compileall` и `git diff --check` — без ошибок.
