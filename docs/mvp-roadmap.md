# План локального MVP к 20 августа 2026

Статус: рабочий план на 2026-08-19. Главная цель — показать понятный локальный HTML по
одной плите без Revit и сервера: четыре входные мозаики, полученные прямоугольные зоны,
метрики по направлениям и итоговую зависимость «масса ↔ число зон» с отдельным числом
физических стержней.

## Что считаем убедительным MVP

Пользователь выбирает комплект одной плиты из четырёх DXF. Программа:

1. разбирает все четыре направления и нормализует размеры в миллиметры;
2. строит для каждого направления несколько допустимых вариантов раскладки;
3. отдельно считает прямоугольные зоны, физические стержни и массу;
4. агрегирует эти показатели по всей плите;
5. строит Парето-график, отмечает автоматически выбранное колено и позволяет посмотреть
   соседние варианты;
6. создаёт автономный HTML и JSON, которые можно открыть локально без внешних картинок;
7. явно показывает инженерные допущения и нарушения валидатора.

Цифры `1/4` из текущего однонаправленного отчёта не считаются результатом MVP. Это
baseline с ручным лимитом, пригодный только для проверки сквозного вызова.

## Порядок реализации

### P0. Зафиксировать семантику — уточнено по готовому проекту

- `len(zones)` — число параметрических зон, `sum(bar_count)` — физические стержни;
- число позиций спецификации — третий показатель после группировки одинаковых стержней;
- `detail_count` пока оставлен как совместимое имя числа зон, но не считается доказанным
  эквивалентом оси графика ТЗ;
- один `LayoutSolution` относится к одной мозаике/направлению;
- итог плиты складывается из четырёх направлений;
- значения графика ТЗ нельзя использовать как нормативное ожидаемое количество.

### P0.5. Добавить инженерный golden-case — выполнено

- плита нуля сопоставлена по четырём направлениям с листами PDF 8-11;
- `pdftotext` извлекает спецификации и проверяет 79 позиций, 1019 стержней и 3177,64 кг;
- `pdftoppm` рендерит решение инженера;
- `scripts/verify_golden_case.py` создаёт автономные `index.html` и `golden.json`;
- интеграционный тест работает на локальном PDF и пропускается в CI без материалов;
- геометрия прямоугольных групп остаётся следующим этапом после DWG→DXF.

### P1. Добавить уровень плиты

- ввести контракты оптимизации `PlateProblem` и `PlateSolution`, не меняя `Mosaic`;
- принимать явный комплект из четырёх файлов или manifest, а не угадывать плиту по
  произвольным именам каталогов;
- валидировать полноту и уникальность направлений `bottom-X`, `bottom-Y`, `top-X`,
  `top-Y`;
- агрегировать `zone_count`, `physical_bar_count`, `total_mass_kg`, статус и диагностику;
- покрыть группировку и агрегацию синтетическими тестами.

### P2. Довести единый конструктор и валидатор детали — выполнена безопасная часть

- ширина строго `k × step`, количество стержней `k + 1`;
- длина учитывает анкеровку не менее `40d` с каждой стороны;
- одна зона не слабее требования накрытых КЭ;
- зоны одного направления не пересекаются и проходят проверку требуемого зазора;
- покрытие КЭ проверяется по геометрии, а не только по центроиду;
- масса всегда пересчитывается общим сервисом;
- каждое правило имеет отдельные тесты для направлений X и Y.

До ответа конструктора используем безопасную семантику без суммирования `As`
пересекающихся зон. Реализованы проверки всех перечисленных правил для X/Y. Для зон с
разным шагом промежуточный зазор получает предупреждение до ответа конструктора;
минимальная ширина пока переводится из КЭ через медианный поперечный размер. Контуры
проёмов ещё отсутствуют во входной модели. Эти допущения видны в `diagnostics/meta`.

### P3. Получить набор вариантов, а не один запуск BSP

- убрать демонстрационное значение `max_details=4` из сценария основной демонстрации;
- использовать полосовой `greedy` как быстрый baseline, а `greedy-priority` — как
  отдельный baseline, пытающийся сначала изолировать самые дорогие цветовые уровни;
- использовать `agglomerative` как быстрый bottom-up baseline, собирающий локальные
  связные пятна в допустимые прямоугольники;
- построить фронт для каждого направления методом `epsilon-constraint`: минимальная
  масса при разных ограничениях на число зон;
- для первого MVP допустим детерминированный baseline, если все варианты проходят общий
  валидатор; CP-SAT/MILP подключается следующим взаимозаменяемым модулем;
- удалять дублирующиеся и доминируемые решения.

### P4. Собрать общий фронт плиты

Для каждого направления сохраняем пары `(n_i, mass_i)`. Общий вариант плиты:

```text
N = n_bottom_X + n_bottom_Y + n_top_X + n_top_Y
M = m_bottom_X + m_bottom_Y + m_top_X + m_top_Y
```

Фронты четырёх направлений объединяются динамическим программированием: перебираются
суммы доступных пар, после каждого шага отбрасываются доминируемые варианты. Это не
смешивает геометрию независимых направлений, но даёт правильную общеплитную метрику.

### P5. Обновить демонстрационный HTML

- паспорт плиты и четыре панели направлений;
- прямоугольники с длиной, шириной, диаметром, шагом и количеством стержней;
- таблица `зоны/стержни/масса/валидность` по каждому направлению и итого;
- общий Парето-график с выбранной «Точкой 3»;
- переключение между соседними вариантами;
- заметная подпись, если использован baseline или неподтверждённое инженерное допущение.
- отдельный переключаемый референс инженера из golden-case; пока он доступен в
  самостоятельном автономном отчёте.

### P6. Проверить перед показом

- модульные тесты агрегации, Парето-фильтра и выбора колена;
- тесты всех инженерных правил X/Y;
- интеграционный тест на одном реальном комплекте из четырёх DXF;
- golden-тест четырёх спецификаций реального PDF;
- `pytest`, Ruff, `compileall`, затем ручная проверка автономного HTML;
- сохранить воспроизводимую команду запуска в README.

## Что сознательно не входит в локальный MVP

- Revit-плагин и построение реальных семейств;
- сервер и публичный деплой;
- PNG-ingest;
- обучение ML на эталонах;
- обещание глобальной оптимальности baseline-алгоритма;
- автоматический разбор закрытых DWG с инженерными эталонами.

После демонстрации приоритеты: получить ответы на открытые инженерные вопросы, добавить
CP-SAT/MILP, конвертировать эталонные DWG в доступный формат и измерить качество против
ручных раскладок.

## Блокирующие данные и вопросы

Для части основного датасета DXF содержит интервалы `As`, но рядом нет `.shk` с
назначением `(диаметр, шаг)`. Для честного расчёта массы нужен один из вариантов:

- совместимые `.shk` для выбранной плиты;
- машиночитаемая Таблица 2.4.2 и правило выбора конфигурации;
- явно согласованный конфигурационный manifest для демонстрационного комплекта.

Для базового локального комплекта совместимые файлы уже определяются: нижние X/Y
используют общую 9-полосную шкалу, верхние X/Y — разные 4-полосные шкалы «2 фона».
Поэтому первый общеплитный MVP можно строить на этом комплекте. Перенос на остальные
плиты без их `.shk` или согласованной таблицы остаётся ограничением.

Также техментор должен подтвердить, считается ли график стр. 6 суммарно по четырём
направлениям и являются ли приведённые числа реальным эталоном или иллюстрацией.
