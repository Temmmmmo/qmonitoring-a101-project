# Гипотезы границы для исходных зон, 16.09.2026

Это read-only опыт на сохранённом отчёте
`artifacts/engineering_variants_2026_09_16/latest-v2/report.json`, а не изменение
алгоритма, физической раскладки или подтверждение Revit-host. Скрипт:

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src artifacts/ga_solver_env/bin/python \
  scripts/experiment_source_zone_boundary.py \
  artifacts/engineering_variants_2026_09_16/latest-v2/report.json
```

Для каждой оси построен tight frame: longitudinal interval
`[demand_lo - 40d, demand_hi + 40d]`, а transverse границы сохранены из
`component.bar_axis_bbox_mm`. Внешний контур — `Polygon(unary_union(cells).exterior)`
с buffer 0,01 мм; отверстия намеренно игнорируются.

| Вариант | Компоненты | current outside | tight inside | tight outside, base inside | tight outside, base outside |
| --- | ---: | ---: | ---: | ---: | ---: |
| Меньше массы (0) | 139 | 57 | 2 | 23 | 32 |
| Меньше позиций (1) | 94 | 55 | 4 | 19 | 32 |
| Меньше стержней (2) | 117 | 51 | 1 | 18 | 32 |

Последние три колонки образуют current outside. Только 2/4/1 случая можно
теоретически исправить укорочением/сдвигом вдоль оси: tight frame уже внутри.
В каталоге `plate-11700` среди них нет меньшей разрешённой длины; это не проверка
раскроя партии. Все 23/19/18 edge cases имеют base frame внутри, но 40d выводит
его наружу. Все 32/32/32 base-outside уже не помещаются с фактической поперечной
шириной: по направлениям это соответственно 4/5/10/13, 3/5/12/12, 3/5/10/14
(bottom-X, bottom-Y, top-X, top-Y); встречаются `genetic-*`, `source-recovery-*`
и единичные `exact-*` зоны.

Это выход выбранных прямоугольных огибающих, **не выход исходных КЭ** и не
недоказанность входной потребности. Удаление лишней каталожной длины не даёт
новых исправлений сверх ранее найденного сдвига 2/4/1; более короткого варианта
из существующего каталога для этих случаев тоже нет.

Для tight-outside: границы глобального bbox вдоль/поперёк/оба/вогнутость =
9/4/0/42, 10/2/0/39, 9/2/0/39. `demand_bbox` сам вне exterior у 50/44/45 зон —
отдельный признак прямоугольной аппроксимации, не доказательство недопокрытия.
Любой допустимый along-frame содержит tight frame; при фиксированной поперечной
оси удлинение или along-shift не исправят tight-outside. Нужны разбиение зоны или
иная геометрия/поперечная ось; достаточность этих мер не проверена.

## Продольное сужение и два поперечных дочерних окна

`scripts/experiment_source_zone_tightening.py` заново гидратирует source-пакет
через общий `build_composite_zone`/`evaluate_composite_coverage`: raw длины,
масса и количество стержней baseline сверяются с packet. Level 0 действительно
`s300d10` без additions; для каждого окна учитывались все КЭ уровней с additions,
без exclusive assignment. Зона не удаляется, если пересечений нет.

| --- | ---: | ---: | --- | ---: | ---: |
| 0 | 17 / 122 | 3105,939330 → 3009,931662 | 139 / 139 / 1196 | 28 → 28 | 57 → 57 |
| 1 | 24 / 70 | 4603,149406 → 4581,512105 | 94 / 94 / 918 | 28 → 27 | 55 → 54 |
| 2 | 22 / 95 | 3425,333184 → 3296,221439 | 117 / 117 / 1071 | 24 → 28 | 51 → 51 |

Во всех трёх: geometry/pattern valid, 0 uncovered cells; численная остаточная
площадь порядка `6e-7 мм²`. Это research-only common-coverage proxy, не
сертификат host/3D/раскроя партии. Новых outside нет; снят только один v1.

`scripts/experiment_source_zone_split.py` проверил первые пять v0 base-outside
зон двумя полосами: `genetic-6`, `source-recovery-6/-8/-10`, `genetic-5`.
Первый прототип, сужавший также transverse bbox, исключён как нерелевантный.
Итоговый метод сохраняет всё transverse окно полосы `[low, cut]`/`[cut, high]`
и сужает только longitudinal core по positive FE-пересечениям.

Рассмотрены 384/41/170/341/103 разрезов по КЭ-изломам или серединам соседних
осей. Принятых нет: соответственно отклонено по empty 1/2/1/45/30, по
min-width 166/39/149/186/73, по изменению или дублю осей 3/0/0/0/0, по local
outside 214/0/20/110/0. Проходящего local-fit нет, поэтому full checker не
запускался. Второй режим разрешал меньше осей, но запрещал дубли: результат не
изменился. Это не исключает иные split/трансверсальные решения.

Примеры варианта «Меньше массы», низ X, Ø10:

- `genetic-4`: потребность X=18338,007…22200,001 мм; минимальная огибающая
  X=17938,007…22600,001, Y=10600…13900 мм. Без выпуска она помещается, после
  40d площадь вне внешнего контура составляет около 0,360 м².
- `source-recovery-6`: потребность X=1807,580…2216,667 мм;
  огибающая после 40d X=1407,580…2616,667, Y=13400…14200 мм. Даже огибающая
  без выпуска уже выходит за контур. Это кандидат на перестроение выбранной
  зоны, не на простое уменьшение каталожной длины.

Для продолжения наиболее обоснован опыт разбиения/сужения логических зон
по фактической геометрии потребности и контура с повторной проверкой полного
покрытия. Новые координаты в экспорт не внесены; 40d, масса, минимальная ширина
и раскрой партии таким опытом не объявляются пройденными.

### Согласованная MVP-гипотеза края: суммарные 80d

Пользователь 16.09.2026 согласовал отдельное MVP-допущение для края: сохраняется
logical core, фаза и поперечные оси, но суммарный запас `80d` может быть
перераспределён вдоль стержня внутрь плиты. Это **не** выполнение прежнего
условия `40d` на каждом конце: его новый interval не сертифицирует.

`scripts/experiment_source_zone_edge_redistribution.py` проверил v0 с исходными
длинами и строгим exterior (отверстия игнорированы). Все 139 исходных компонентов
проходят старое per-end `40d` и суммарные `80d`; после переноса 25 из 57 outside
frames помещаются, новых outside нет. Для 32 оставшихся поиск по 101 равномерной
пробе interval плюс концам не нашёл fit (bottom-X/Y/top-X/top-Y: 4/5/10/13);
это не доказательство, что непрерывного fit нет. Из 107 компонентов с найденным
fit у 23 уже нет `40d` на каждом конце, но у всех 107 сохранены core containment
и суммарные `80d`; invalid total-80d нет. Логическое coverage не пересчитывалось
как «физическое»: prior common checker для неизменных core/phase/axes давал
0 uncovered и geometry/pattern valid. Поэтому это только edge-assumption для
дальнейшего review, не host/3D/анкеровка/раскрой партии.

Пример `bottom-X/genetic-4`, Ø10: исходная длина 4875 мм не меняется;
потребность X=18338,007…22200,001 мм. Сдвиг −506,503 мм помещает огибающую
в X=17325,001…22200,001 мм: запас слева 1013,006 мм, справа 0 мм.
Потребность остаётся внутри, суммарный запас превышает 800 мм, но прежнее
условие 400 мм с каждого конца не выполнено. Это наглядное различие профилей.
