# Стадия A — Ingest-парсер. Спецификация задачи

**Цель:** прочитать файл-мозаику (сначала DXF) и вернуть нормализованную модель
`Mosaic` (см. `src/rebar/models.py`), с которой работает весь остальной пайплайн.
Плюс простой рендер для визуальной сверки.

> Контекст обязателен: [`docs/context.md`](context.md) §2 (форматы), §3 (подписи), §8
> (соглашения). Контракт данных — `src/rebar/models.py`, **сигнатуры не менять**.

## Реализовать

### 1. `legend.py`
- `parse_spec`, `parse_label` — **уже реализованы**, использовать как есть.
  Для подписей с тремя и более слагаемыми текущая рабочая семантика: первый токен —
  основной фон, последний — дополнительная арматура; промежуточные фоновые слои в
  `Band` пока не представлены. Такие подписи реально встречаются в шкалах «2 фона».
- `parse_shk(path) -> list[(threshold_as, label)]`
  - формат: пары `float32` LE = пороги; подписи `re.finditer(rb'[ -~]{5,}')`; каждая
    подпись хранится дважды — дедуплицировать, сохранить порядок.
  - эталон (`К09_фп_Вх.shk`): `[(8.48,'s300d18'), (16.97,'s300d18+s300d18'),
    (25.45,'s300d18+s150d18'), (29.43,'s300d18+s150d20'), (39.90,'s300d18+s100d20'),
    (57.57,'s300d18+s100d25')]` (пороги ±0.05).
- `build_legend(shk_path, aci_order) -> list[Band]`
  - собрать `Band` из порогов+подписей (`parse_label` для background/additional) и ACI
    из `aci_order` по позиции; `index` = позиция от фона.
  - валидация: если `len(aci_order)` не согласуется с числом полос — понятная ошибка/лог.

### 2. `dxf_ingest.py`
- `direction_from_filename(name) -> Direction` — распознать `layer` (Нижнее/Верхнее) и
  `axis` (ОСИ Х/У, латиница X/Y). Учесть кириллические `Х`/`У`. Учесть варианты имён из
  датасета: `Нижняя по Х`, `Верхняя по У`, `Х Верх`, `У Низ`, `X_у_нижней_грани`.
- Автоопределение единиц входа (метры/мм): сначала `$INSUNITS`, для unitless/R12 —
  эвристика по медианному размеру ребра КЭ. Выбор и коэффициент сохранять в `meta`.
- `extract_scale_aci_order(doc) -> list[int]` — ACI полос шкалы по порядку из блока
  `KLEENKA` (сущности `SOLID`). Зафиксировать соглашение о направлении порядка и
  согласовать с `.shk`.
- `read_mosaic(dxf_path, shk_path=None) -> Mosaic`:
  1. `ezdxf.readfile`; modelspace.
  2. Брать `3DFACE` только слоя `KLEENKA`; парные сущности `PLAST` отбрасывать.
  3. Удалить повторную `vtx3` у треугольных КЭ, посчитать центроид полигона.
  4. Нормализовать координаты в мм.
  5. Извлечь ACI и числовые границы `As` из `KLEENKA`.
  6. При наличии совместимого `.shk` собрать `Band`; иначе оставить `legend=[]`,
     `Cell.band=None`, а интервалы сохранить в `Mosaic.meta`.
  7. Посчитать `bbox`; определить `direction` из имени.

При автоматическом выборе `.shk` нельзя считать один файл глобальным: сначала требуется
совпадение числа полос с DXF, затем при нескольких кандидатах учитывается ось X/Y. Если
кандидат остаётся неоднозначным, `shk_path` должен быть передан явно.

### 3. `render.py`
- `render_mosaic(mosaic, out_path)` — залить каждый `Cell` цветом `aci2rgb(cell.aci)`,
  сохранить PNG. Ось Y перевернуть под растр. Для визуальной сверки с исходным PNG.

## Критерии приёмки (tests/)
Гонять на реальных файлах из `Дополнительные материалы/` (пути с кириллицей — через фикстуры):
1. `parse_shk` на `К09_фп_Вх.shk` возвращает эталонные 6 полос (пороги ±0.05, подписи точно).
2. `parse_label('s300d18+s150d20') == (Rebar(300,18), Rebar(150,20))`;
   `parse_label('s300d18') == (Rebar(300,18), None)`.
3. `read_mosaic` на «Нижнее армирование вдоль ОСИ Х.dxf»:
   - `len(cells) == 2132`, при этом исходных `3DFACE` 4264;
   - `bbox` ≈ (0,0, 23600,14000) мм (после ×1000), допуск ±5%;
   - все `cell.aci` — валидные int; у части `needs_extra == True`, у большинства — фон;
   - `direction == Direction(Layer.BOTTOM, Axis.X)`.
4. `render_mosaic` создаёт непустой PNG; визуально совпадает с исходным (проверка глазами).
5. Валидация легенды: расхождение числа полос .shk ↔ ACI не падает молча.
6. **Единицы:** `read_mosaic` даёт одинаковый bbox в мм (±5%) независимо от единиц входа —
   проверить на файле в метрах (наши примеры) и, если появится, в мм; либо синтетически
   промасштабировать координаты и убедиться, что `detect_units_scale` компенсирует.
   Дополнительно прогнать `read_mosaic` на всех 4 направлениях нескольких плит из
   `Для верификации изополей 2/_Задания/` — не падает, bbox правдоподобен.
7. Все 24 DXF из «Для верификации изополей 2» разбираются; интервалы `As` заполнены.
