## Что проверено по реальным данным

Снимок `revit_info/060_notest/qmonitoring-full-plate-20260914-102249-013000.json`
содержит рабочую плиту `11020633`, `Пм-1`, из
`VTNK-02_RD_KR_K09_KJ2.3-14_отсоединено`. Статус `blocked_setup` возник после
отмены типов арматуры, а не из-за ошибки чтения плиты. `read_issues=[]`.

- Толщина 200 мм; верх/низ Z=7110/6910 мм в Revit internal.
- Защитные слои: сверху/снизу 40 мм, сбоку 25 мм.
- По 47 отверстий в верхнем и нижнем сечениях.
- 241 плоская грань, все нормали вдоль осей, все рёбра — отрезки.
- Есть уступ на Z=7010: нижнее сечение 305,6603 м², верхнее 305,6063 м².
- Восстановленный объём 61,12666 м³ совпадает с сериализованным Revit Solid.

Это не прямоугольник и не простая экструзия одного внешнего контура. Даже
верхняя и нижняя границы отличаются на 0,054 м². Некоторые грани Revit
содержат несколько раздельных копланарных участков: второй loop не обязательно
отверстие. Рёбра в loop могут иметь разное направление; порядок начала/конца
не использован как определение материала.

## Изменения кода

`optimization/services/solid_host.py` восстанавливает сечения по всем
горизонтальным граням и всем высотам вершин. Независимо проверяются **все**
боковые грани, стенки отверстий, нормали, замкнутость, длины рёбер, совпадение
верхнего/нижнего снимков, габариты и объём. Пропущенные/дублированные грани,
дуги, наклонные поверхности и ошибки чтения дают отказ. Никакой подмены bbox,
автоматического исправления полигонов или удаления отверстий нет.

Для устранения численного шума сериализации координаты округляются к
0,00001 мм. Это техническая точность геометрии, не инженерский допуск.

`application/working_solid_host.py` и `scripts/check_working_revit_host.py`
проверяют всю физическую партию относительно этого Solid. При заданных четырёх
глубинах считается объём каждого охватывающего прямоугольного тела стержня
с защитными слоями вне всех высотных сечений. Геометрия envelope совпадает
с существующей консервативной native-проверкой Full/Physical Plan Trial.
Прямоугольное тело несколько завышает круглое сечение на углах.

Без глубин выдаётся только XY-проверка необходимого условия по объединению
сечений и консервативная проверка их пересечения. Положительный XY-результат
**не** объявляется допустимой 3D-укладкой. XY-сдвиги и источник/гипотеза привязки
обязательны; значений по умолчанию нет. Полные source-сертификаты пакета
CLI отдельно проверяет независимым валидатором pyRevit.

Старый `qmonitoring-host-input/v1` и прямоугольные оптимизаторы не расширены
молчаливо. Новый сервис — проверка фактической геометрии, ещё не host-aware
пересчёт всей оптимизации. Публичный `models.py` не менялся.

Отдельно исправлена потеря `host/host_id/read_issues` при отказе в параметрах
Full/Physical Plan Trial до создания плана. Сначала сохраняется фактическое
чтение, потом проверяются типы и глубины. Обёртки дополняют только отсутствующие
поля; native-данные и замечания не заменяются прежним setup-снимком другой плиты.

## Эксперимент с полной раскладкой

Реальный снимок получен со **старым фундаментным** пакетом 2531 стержень /
37,94 т. Он не является результатом испытания новых 902 стержней. Геометрию
плиты из него можно читать независимо от старого входного пакета.

Новую партию взяли из
`artifacts/assistant_pipeline_fresh_2026_09_13/physical-bar-plan-trial.json`:
902 стержня, 2989,953486 кг, все четыре направления. Ничего не удаляли,
не укорачивали и не пересчитывали с ослабленной потребностью.

**Гипотеза:** Revit XY = DXF XY. Она не подтверждена в рабочей модели.

| Направление | Всего стержней | Вне объединения сечений с cover | Вне общего для всей толщины контура |
| --- | ---: | ---: | ---: |
| Нижнее X | 164 | 62 | 62 |
| Нижнее Y | 98 | 64 | 64 |
| Верхнее X | 365 | 173 | 175 |
| Верхнее Y | 275 | 123 | 123 |
| Всего | 902 | **422** | **424** |

422 — нарушение необходимого XY-условия даже без выбора глубины. Ещё два
результата зависят от уступа по высоте. Оставшиеся стержни пока не получили
3D-допуска. Эти проверки не связаны со счётчиком 12 взаимных пересечений
дополнительной арматуры: это другой класс ошибок.

Результат: `artifacts/revit_working_host_checks_2026_09_14/zero-offset-hypothesis-v2.json`.
SHA256 исходного снимка:
`55e149edc847aa1d7c70051bf5182b618266d1dd76df00ff73c5091e1b5a23bc`.
SHA256 проверенной физической партии:
`6922edea35976864588f20bd3f0e6da9f7ca578d8b4cf3a5bd36c1023d3fdad3`.

Таким образом, старые показатели массы/количества остаются показателями
расчёта по DXF, **не** доказательством пригодности к этой рабочей плите.
Просто создать всю нынешнюю партию с нулевым сдвигом не получится.

## Воспроизведение

```bash
PYTHONPATH=src artifacts/ga_solver_env/bin/python scripts/check_working_revit_host.py \
  --report revit_info/060_notest/qmonitoring-full-plate-20260914-102249-013000.json \
  --packet artifacts/assistant_pipeline_fresh_2026_09_13/physical-bar-plan-trial.json \
  --offset-x-mm 0 --offset-y-mm 0 \
  --binding-source 'Research hypothesis XY=0; not measured or approved in working RVT' \
  --output artifacts/new-working-host-check.json
```

Без `--packet` считывается только геометрия, привязка не требуется. Опциональный
`--axis-depths-mm` принимает четыре **явных** числа в порядке bottom-X,
bottom-Y, top-X, top-Y, от соответствующей грани до оси. Этот документ не
задаёт их численные значения и не согласует порядок укладки.

Выход — новый JSON; существующий файл не перезаписывается. Статус
`blocked_host_under_explicit_binding` — успешная диагностика несовместимости,
не разрешение создавать часть партии. Пропущенные стержни отсутствуют.

## Что нужно следующим от Revit

Новый единый read-only снимок выбранной **рабочей плиты и её DXF**.
Старый CAD051 проверял другой документ, тестовую плиту и другой DXF; его
нулевую привязку переносить нельзя. Обычный старый CadProbe также ищет
зашитые тестовые IDs, поэтому для рабочего сценария нужна отдельная кнопка
Working Host Probe без типов арматуры, глубин, создания или отката.
[Архив и короткое сообщение специалисту](../REVIT_NEXT_STEP_2026-09-14.md).

Новый `revit-working-host-cad-probe/v1` принимается offline-проверкой host,
если состояние документа не изменилось, `host_read_issues=[]` и идентификаторы
совпадают. Ошибки CAD при статусе `partial` не превращаются в подтверждение
привязки: они сохраняются в результате, а проверка касается только полного
снимка плиты. Для одного host и двух CAD-чтений введён явный лимит 32 MiB;
старые загрузчики по умолчанию сохраняют предел 8 MiB.

После привязки необходимо отдельно разобрать несовпадение отверстий в DXF
и RVT и строить раскладку с настоящим host. Исходный спрос нельзя молча
удалить в новых отверстиях. Высоты/фон, оставшиеся стыки и сквозная проверка
создания в Windows/Revit по-прежнему не закрыты.
