## Что проверяет разработчик

Команда после получения отчёта:

```bash
python3 scripts/verify_revit_dxf_calibration.py \
  --dxf 'путь/Верхнее армирование вдоль ОСИ Х.dxf' \
  --shk 'путь/К09_фп_2 фона_Вх.shk' \
  --report 'путь/qmonitoring-cad-….json' \
  --output 'artifacts/revit_probe/новая-сверка-cad.json'
```

Выход — новый файл, существующие файлы не перезаписываются. Exit 0 означает
`geometry_matches`, exit 1 — `blocked`; это не код разрешения на размещение.
Приложение использует `read_mosaic`, не собственный parser/определитель единиц.
SHA256 исходного DXF и отчёта связывают результат с конкретными входами.

В исходнике 2132 КЭ, 2209 уникальных вершин, 4225 треугольников при разбиении квадов.
Контрольные вершины выбираются из реальных узлов: (0,0), (23600,14000), (0,14000) мм.
Для текущей identity-матрицы ожидаются те же XY; CAD Z = −8970 мм, **не** Z арматуры.
Ширина/высота плиты 23600 × 14000 мм. Bbox всей CAD-вставки содержит также шкалу
и подписи, поэтому не является габаритом мозаики.

Проверяется весь меш: вершины с допуском 0,1 мм, принадлежность треугольников каждому
КЭ и отсутствие потерь/дубликатов. Для выпуклого квада разрешены обе диагонали,
но не произвольное переустройство сетки. Перенос/поворот берётся из записанного
GetTransform и проверяется, а не подгоняется по bbox. Отражение, наклон, масштаб
не 1 после нормализации и неоднозначное соответствие блокируются.

У связи отдельно проверяется SHA256 доступного локального файла. Это сверка файла
на диске, **не** доказательство актуальности цветов/спроса закэшированной CAD-геометрии.
У импорта этот гейт остаётся `not_checked`. Совпадение XY-bbox с плитой — только
проверка габаритов, не containment стержней/проёмов. `placement_eligible=false` всегда.

Если Revit объединил соседние грани и потерял исходные узлы/разбиение, первая версия
сверки вернёт отказ. Полученный полный readback позволит разобрать это без угадывания
координат и без размещения арматуры. Успех симуляции ниже не гарантирует успех Revit API.

## Основание для работы с API

`GetSymbolGeometry()` возвращает локальную геометрию; она переводится в систему модели
цепочкой `GeometryInstance.Transform`, каждый уровень ровно один раз. Это соответствует
[примеру Autodesk для Revit 2024](https://help.autodesk.com/cloudhelp/2024/ENU/Revit-API/files/Revit_API_Developers_Guide/Revit_Geometric_Elements/Geometry/GeometryObject_Class/Revit_API_Revit_API_Developers_Guide_Revit_Geometric_Elements_Geometry_GeometryObject_Class_GeometryInstances_html.html).
`GetTotalTransform` остаётся диагностикой и повторно к готовым точкам не применяется.
Абсолютный путь связи получается через
[ExternalFileReference.GetAbsolutePath](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/22f83514-5da8-bbf1-33e5-94e6212b53fe.htm).
Эти API-проверки и offline doubles не заменяют запуск в целевом Revit 2024.
