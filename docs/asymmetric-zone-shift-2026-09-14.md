# Несимметричное положение зоны внутри плиты

Пользователь согласовал смещение зоны внутрь плиты **без обрезки стержня**, после
разбора крайних зон на инженерской иллюстрации. Сдвиг не означает перенос исходного
спроса или ослабление анкеровки. Картинка сама по себе не задаёт измеренные концы,
узел опоры или инженерное разрешение на уменьшение требуемой длины.

## Два различных перемещения

Продольное: при исходном требуемом интервале `[a,b]`, установленной длине `L` и
контрольной анкеровке `e=40d` допустимые начала стержня находятся в
`[b+e−L, a−e]`. Свобода равна `L−(b−a)−2e`, а не произвольной половине длины.
Установленную длину можно расположить несимметрично, пока сохраняется каждый конец
требуемого участка с анкеровкой. При нулевом запасе свободного сдвига нет.

Это уже разрешал общий валидатор. Новая подгонка `fit_composite_zone_to_solid_host`
расширяет операцию на точный ортогональный Solid с вырезами и отверстиями и требует
**один общий продольный сдвиг всех стержней всех компонентов зоны**. Используется
пересечение материала всех высотных сечений; это консервативная XY-проверка,
не проверка реальных высот арматуры. Зоны, которые не помещаются, не удаляются.

Поперечное: перемещается окно выбора осей, но не глобальная сетка/фаза. Например,
для условного @150 окно `[-150,450]` выбирает оси `−100,100,200,400`, а `[0,600]`
выбирает `100,200,400,500`. Число стержней остаётся четыре. Исходный КЭ с поперечным
интервалом `[0,300]` обслуживается в обоих случаях, но внешняя ось заменена внутренней.
Это не равномерный шаг150: сохраняется фактическая последовательность100/200.

Граница окна выбора не равна телу стержня и не должна автоматически отступать от
края плиты на cover+radius. Проверяются именно выбранные физические оси и тела.
`propose_transverse_zone_translations` сохраняет ширину, длины, диаметры, количество,
STO-шаблон и каждую положительную часть исходного КЭ, которую обслуживала эта зона.
Кандидаты строятся по событиям смены выбранных осей. Ограничение числа кандидатов
явно протоколируется; это не доказательство глобальной невозможности.

## Полная проверка и связь с существующим сценарием

`application/asymmetric_zone_shift.py` выбирает перемещения с учётом текущего
положения остальных зон: новые пересечения тел одного направления запрещены.
Далее заново проверяются исходное покрытие, полный состав партии, масса,
позиции спецификации, раскрой и host. Это конечная эвристика, не глобальный optimum.
Рабочие отметки Z, фон, X/Y-коллизии и нормативная анкеровка остаются отдельными
проверками; ни код, ни отчёт не выдают инженерного разрешения.

Для существующих пар недостаточно сохранения их количества/ID: при сдвиге окно
может выбрать другую ось, а продольный нахлёст — вырасти. Поэтому фактическая область
пересечения тел после перемещения должна содержаться в прежней (допуск 0,001 мм²).
Проверка повторяется для выбранного кандидата и всего конечного результата.
Суммарный поперечный сдвиг ограничивается относительно исходного окна, а не заново
от каждого промежуточного положения в следующем проходе.

Важное различие исходных данных: нынешние **139 параметрических зон** разворачиваются
в **1196 стержней / 3105,93933 кг / 28 позиций** после балансировки раскроя.
**902 стержня / 2989,953486 кг / 25 позиций** — другая, уже нормализованная физическая
партия. Это не те же139 исполняемых прямоугольников; смешивать уровни нельзя.

Новый CLI восстанавливает именно полный параметрический источник по свежим DXF и
неизменным файлам конвейера. После сдвига формирует новые zone-drafts и новые
сертификаты покрытия через существующие сервисы. Опциональное `--normalize`
снова вызывает прежний нормализатор с записанной конфигурацией и повторную проверку
реального host. Старые902 стержня и ранее отправленный Revit-пакет не перезаписываются.

## Результат на рабочей плите

Два полных запуска с одним источником `plate:52` и тем же реальным Solid:

| Режим на исходных зонах | Стержни с отказом по host до / после | Пары пересечений до / после | Перемещено зон |
| --- | ---: | ---: | ---: |
| Только общий продольный сдвиг | 503 / 503 | 399 / 399 | 0 |
| Продольный + поперечный выбор осей, до 600 мм | 503 / 501 | 399 / 399 | 2 |

Во всех случаях сохранены 139 зон, 1196 стержней, 3105,93933 кг и 28 позиций; раскрой
повторно имеет `pass`. Все 1636 требующих КЭ четырёх направлений покрыты в прежнем
research-профиле: 450/335/447/404, непокрытых 0. Исходные значения и полигоны не менялись.
Проходов 2, усечения пула нет. Продольный вариант занял 25,305 с; объединённый вместе
с последующей нормализацией и host-проверкой — 43,533 с.

Изменились окна `bottom-Y/source-recovery-7` на +50,000005 мм и
`top-Y/source-recovery-38` на −33,964005 мм; продольные интервалы в принятом варианте
не изменились. Малые дополнительные миллионные доли миллиметра — представитель
открытого интервала выбора дискретных осей, не настройка шага или физический зазор.
Фактические наборы осей здесь @300: низY `[-200,100,400] → [100,400,700]`, верхY
`[9700,10000,10300] → [9400,9700,10000]`. Сдвиг окна на50/34мм нельзя описывать
как перемещение каждой физической оси на ту же величину: изменяется выбор осей
из прежней глобальной сетки.

После **повторной нормализации с прежней конфигурацией** получены те же 902 стержня,
2989,953486 кг, 25 позиций и 12 неразрешённых пар. Host-отказы на этом этапе
**406 → 404** относительно прежнего конвейера **до обхода малых отверстий**.
Нельзя сравнивать 404 с ранним 371 как улучшение: 371 получен другим, дополнительным
FE-repair после обхода отверстий. Исходные 503/399 также нельзя смешивать с
нормализованными 406/12.

Затем новый источник проверен совместно с **обоими прежними этапами коррекции**:
обходом малых отверстий и FE-repair с обменом существующих длин. Для этого добавлен
`scripts/experiment_shifted_physical_repair.py`: он заново читает исходные DXF,
проверяет цепочку нового отчёта/нормализации/сертификатов и строит области
обслуживания именно новых осей. Старый сертификат неизменённых осей не используется.

| Последовательный этап физической партии | Прежний источник: host-отказы | После сдвига зон: host-отказы |
| --- | ---: | ---: |
| Нормализация и подгонка к host | 406 | 404 |
| Обход малых отверстий | 405 | 403 |
| Совместный FE-repair с обменом длин | 371 | **369** |

Таким образом, улучшение относительно прежнего лучшего результата — **два стержня**,
а не все 37 изменений последнего solver. Последний этап заново изменил 37 стержней
и устранил 34 отказа; вместе с новым сдвигом сохранены **902 стержня / 2989,953486 кг /
25 позиций**, весь инвентарь сталь/диаметр/длина/количество и безотходный раскрой.
Покрыты все 1636 исходных требующих КЭ, непокрытых 0; остаточные пары **12 → 12**,
новых нет, изменённые на FE-этапе стержни в пересечениях не участвуют.

В FE-пуле 17613 кандидатов, усечения нет; все три цели решены до optimum **внутри
этого конечного пула**, не среди всех возможных раскладок. Полный дополнительный
прогон с повторным чтением источников занял 27,290 с. Отчёт:
`artifacts/asymmetric_zone_shift_2026_09_14/combined-fe-repair-v1.json`, SHA256
`fa1cc5e6b778bee80e691f2bc245bf81e6e3a43a380ee8dfa1f58cbaecd5fe5e`.
Его статус **`blocked_host`**, `placement_eligible=false`: 369 отказов не скрыты.
Как и прежний FE-repair, это физическая исследовательская партия, не автоматически
перегруппированные прямоугольные зоны и не пакет Revit.

Финальный независимый аудит выполнен **без повторного solver**: повторный ingest
DXF, новая сертификация областей обслуживания и отдельная геометрическая проверка
подтвердили нулевую непокрытую площадь и сохранение всех исходных частей КЭ.
У 892 стержней с положительным спросом проверены полные40d;10 без спроса не менялись.
Host-отказы низX/низY/верхX/верхY: **51/49/169/100**, в прежнем лучшем варианте
**51/50/169/101**. Сопоставление фактических тел старой и новой партий:12 пар,
ни новой, ни увеличившейся, ни переместившейся области пересечения. Проверены все23
SHA256 источников и код; раскрой дополнительно сверён по свидетельству раскроя:
333 исходных прута11700мм,902 установленные детали, нулевой отход в принятой модели.

Вывод: допустимая поперечная асимметрия дала небольшое реальное улучшение,
но общий продольный сдвиг существующих зон не решил конфликт. Приём не устраняет
нехватку места для необходимой анкеровки и не превращает результат в готовую выдачу.
Остаток полностью сохранён в отчёте со статусом `blocked_working_host`.

Артефакты: `artifacts/asymmetric_zone_shift_2026_09_14/along-only-v1/` и
`artifacts/asymmetric_zone_shift_2026_09_14/combined-v1/`.
SHA256 объединённого `experiment.json`:
`2fc754d501146c0167e71f778d080dbb32f95aeb3ba23881b4bb979d5e9c9a62`.

Финальная полная регрессия: **2760 passed**,147,77с,3 прежних предупреждения openpyxl;
187 новых тестов (54 точного продольного fit,38 поперечных кандидатов,34 совместного
приложения,28 CLI/цепочек SHA и33 продолжения до физического FE-repair). Ruff для
src/tests/scripts, compileall и diff-check прошли. Независимый повторный ingest DXF и построение
физических сертификатов подтвердили весь исходный спрос, раскрой и сохранность
пересечений; изменённые стержни не участвуют в остаточных пересечениях.

## Воспроизведение

```bash
PYTHONPATH=src python scripts/experiment_asymmetric_zone_shift.py \
  --pipeline-dir artifacts/revit_delivery_2026_09_14/host-aware-v1 \
  --snapshot artifacts/assistant_recovery_stock_2026_09_13/k09-typical-3-14-plate-11700.json \
  --candidate-id plate:52 \
  --working-host-report qmonitoring-working-host-20260914-122250-368000.json \
  --confirm-identity-xy \
  --maximum-transverse-shift-mm 600 --maximum-candidates-per-zone 32 \
  --maximum-passes 2 --normalize \
  --output-dir artifacts/asymmetric_zone_shift_2026_09_14/combined-v1
```

Выходной каталог должен быть новым. `experiment.json` различает источники1196 и
нормализованную партию, содержит ссылки/SHA256, исходные и итоговые метрики.
`shifted-patterned-analysis.json` — новый проверенный по исходному спросу
параметрический результат, **не разрешение размещения**. CLI ничего не отправляет
в Revit и не собирает автоматически архив для специалиста.

Продолжение до сопоставимого прежнему лучшему физического результата:

```bash
PYTHONPATH=src python scripts/experiment_shifted_physical_repair.py \
  --shifted-dir artifacts/asymmetric_zone_shift_2026_09_14/combined-v1 \
  --snapshot artifacts/assistant_recovery_stock_2026_09_13/k09-typical-3-14-plate-11700.json \
  --candidate-id plate:52 \
  --working-host-report qmonitoring-working-host-20260914-122250-368000.json \
  --confirm-identity-xy \
  --output artifacts/asymmetric_zone_shift_2026_09_14/combined-fe-repair-v1.json
```

Выходной файл также должен быть новым. Ни этот JSON, ни исходный исследовательский
отчёт нельзя загружать в Plan Preview или Physical Plan Trial. Revit-специалисту
сейчас не требуется повторять прежний запуск: рабочая геометрия и графический
перенос уже получены; новый пакет для размещения эта итерация не создаёт.
