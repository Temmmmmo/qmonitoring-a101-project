# Удаление избыточных отрезков после обрезки по отверстиям

Гипотеза: часть коротких отрезков и дубликатов можно убрать, не потеряв ни одной
ранее покрытой части исходных КЭ. Проверяется точная геометрия, отдельно для
наличия стали и главной ветви с контрольными 40d; число непокрытых КЭ само по себе
не является доказательством. Остальные стержни, их оси/Z/диаметры/длины/владельцы
буквально неизменны; каждый удалённый ID остаётся в явной карте происхождения.

Реальный вход: `boundary-trim-openings-web-v1`, заново проверенный по исходным DXF,
зонам и рабочему host с отверстиями. Полное тело оставшихся стержней помещается
в материал; cover по текущей выбранной политике не добавляется.

Это улучшение количества/массы/позиций, **не устранение исходного недопокрытия**

допуск округления не выдумывались; удлинение и объединение через отверстия не
выполнялись. Если исходный раскрой прошёл, предложение, теряющее этот pass,
откатывается. Размещение и инженерное подтверждение остаются `false`.

## Подключение к web

Для К09 режим «Обрезать по границе плиты и отверстиям» теперь выполняет этот
cleanup **после** полного trim. Обычный расчёт без Working Host не изменён.
`boundary_trim_web_report(..., cleanup_redundant=True)` включает этап явно;
низкоуровневый default остаётся trim-only. Cleanup не переносится автоматически
на другие ремонтные алгоритмы и не является унификацией/округлением длин.

`application/trimmed_cleanup_web.py` сверяет графическую партию обрезки с её
типизированными стержнями, запускает поиск и независимый checker. Новый
`output_kind="pruned-trimmed-physical-bars"`: метрики, SVG, совмещённый слой зон
и ведомость относятся к оставшимся стержням. Исходные изополя и 139 зон неизменны.
`boundary_trim` хранит прежнюю проверку всей партии после реза, `trimmed_cleanup`
содержит новые проверки до/после удаления. Старые 14 пар не выдаются за новый
счётчик: после cleanup их 12. Проверка cover после удаления явно `not_checked`,
не скопирована из старой партии; материал с отверстиями проверен заново без cover.

Скачивается **новый** `graphic-bar-plan-pruned/v1`, не усечённый старый пакет:

- `source_trim_packet` — полный неизменный `graphic-bar-plan-draft/v1`;
- `source_trim_packet_json` — точный UTF-8 JSON этого пакета, а
  `source_trim_packet_sha256` — SHA256 этих байтов. Нельзя пересериализовывать
  словарь IronPython для проверки этого хеша: порядок ключей может отличаться;
- `retained_bar_ids` — уникальные `{direction, bar_id}` из финальных направлений
  вложенного trim-пакета, без новой геометрии;
- `expected` — `physical_bar_count`, `additional_mass_kg`, `position_count`,
  `source_zone_count`, рассчитанные по оставленной партии;
- `cleanup` — полный `trimmed-length-cleanup-check/v1`, включая явную карту
  каждого входного ID в `[тот же ID]` либо `[]`, покрытия, раскрой и 3D-пары;
- `geometry_kind="straight-bars-only"`,
  `source_stage="redundant-trimmed-bars-pruned"`; разрешения размещения и
  инженерного подтверждения остаются `false`.
