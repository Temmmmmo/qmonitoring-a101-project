# К09: Revit меняет оси при создании арматуры

## Проверенный живой запуск

Источник — локальный `qmonitoring-rebar-review-20260916-143116-233000.json`
в корне проекта; персональные пути и сам отчёт не публикуются.
Rebar Review 0.1.3, Пм-1 (11020633), правильная партия 918 стержней,
XY = 0;0, автоматические глубины низ X/Y, верх X/Y = 46;62;48;68 мм.

Revit создал все 918 элементов, но чтение перед Commit обнаружило изменения
осей у **73 стержней**, у **51 из этих 73** также изменилась длина.
Это не 124 разных стержня и не число упавших программных тестов.

| Направление | Стержней с изменённой осью |
| --- | ---: |
| Низ X | 3 |
| Низ Y | 3 |
| Верх X | 26 |
| Верх Y | 41 |

Высоты всех осей совпали с планом. Наибольшее изменение координаты — 13 мм,
оно значительно больше допуска чтения 0,01 мм. Масса по считанным осям
2864,705580 кг вместо 2864,768771 кг. Малое изменение общей массы не делает
неверные координаты допустимыми.

Примеры (координаты в мм):

- `bottom-X/required-union-0-28`: план от (3709,461;700;6956) до
  (8584,461;700;6956), обе конечные точки сместились по Y на +11 мм.
- `bottom-Y/source-recovery-5/0/1`: X = 10000, Y = 2237,2735…10037,2735,
  Z = 6972; обе точки сместились по X на +10 мм.
- `top-X/flat-repair-2678`: от (22230;12994;7062) до (23400;12994;7062);
  конец удлинился по X примерно на 5 мм.

Статус `failed_rolled_back`: группа откачена, Commit не выполнялся,
добавленных/удалённых ID после отката нет, host не изменился.
Это подтверждённая работа отката, а не сохранённая арматура.

## Причина и проверяемая гипотеза

Вероятная причина — автоматические привязки Revit. Autodesk описывает
автоматическое притягивание стержней к защитному слою и другим стержням,
а также назначение собственных предпочтительных привязок:
[описание типов привязок](https://help.autodesk.com/cloudhelp/2023/ENU/Revit-StructEng/files/GUID-3270A249-31BF-427A-960E-B1292ECFE8F5.htm).
Имеющийся отчёт не содержит целей привязок: конкретные элементы, вызвавшие
каждый сдвиг, пока не установлены. Не утверждаем, что все 73 случая имеют
одну доказанную причину.

Гипотеза исправления: у новых смещённых стержней назначить фиксированные
расстояния до плоских граней выбранной плиты, восстанавливающие исходные оси.
Подтверждённый Autodesk принцип — задать не только предпочтительную цель,
но и её расстояние; знак расстояния существенен:
[пример Autodesk Developer Network](https://blog.autodesk.io/boundary-elements-and-stirrup-constraints/).
Пример относится к хомутам и не является живой проверкой нашей прямой партии.

Не менять существующий фон, глобальные настройки Revit, JSON раскладки или
допуск 0,01 мм. Знак смещения проверять по фактической геометрии, не угадывать.
Неизвестная привязка или повторное несовпадение — диагностический отказ и
откат всей партии, а не пропуск стержня. Итоговый критерий — полное совпадение
918 нативных осей до и после Commit, затем явное подтверждение сохранения.

## Поставка 0.1.4 и локальная проверка

Реализован один проход после общего Create → Regenerate: только сместившиеся
оси получают фиксированные привязки, затем выполняется повторная полная
сверка. В JSON добавлена диагностика `axis_constraint_control`. Число назначенных
привязок не считается числом успешно исправленных стержней до итогового чтения.

`tests/integrations` и `tests/web/test_revit_tools.py`: **1049 passed**, 16,36 с,
одно предупреждение об устаревшем lib2to3. Проверены знаки смещений, обратная
ориентация оси, неизменённые стержни, ошибки назначения/откат, грамматика Python 2,
план всей К09 на снимке и состав ZIP. Ruff и `git diff --check` проходят.
Живой запуск исправления 0.1.4 ещё не выполнен.

Архив: `downloads/qmonitoring-rebar-review-mvp-0.1.4-code-only.zip`,
SHA256 `a34cdb0066cd5ed88afd930af69522f91c4181db49c14a7411f8b61680ba0a9d`.
Только 19 файлов кода/инструкций/манифеста, исходные материалы в ZIP не включены.
Специалисту нужен тот же JSON на 918 стержней, Пм-1, XY 0;0 и автоматические
46;62;48;68 мм. Инструкция повторного запуска находится внутри ZIP.

## Что это не закрывает

Успех переноса осей не означает инженерную приёмку К09. В исходной партии
остаются 10 КЭ без полного геометрического покрытия, 143 КЭ отдельного
контроля 40d и непрошедший раскрой 11700 мм. Геометрия существующего фона и
коллизии при фактических высотах не подтверждены. Подробности:
[К09: контроль и доставка](k09-delivery-2026-09-16.md).
