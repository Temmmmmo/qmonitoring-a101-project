# Обход малых отверстий без загибов

14 сентября 2026. Пользователь согласовал только сдвиг прямых стержней внутри зон
по правилу предоставленного инженерского комплекта; загибы, муфты и сварка не входят.
Новая коррекция не подменяет основной результат `LayoutZone`: исходные зоны
сохраняются, изменения исполнительных осей оформляются отдельным черновиком.

## Проверяемая область метода

На листах дополнительного армирования сопоставленного комплекта К09, PDF страницы
9–10 (печатные листы 7–8), разрешён сдвиг попадающих на отверстия шириной менее
300 мм стержней внутри зоны при сохранении общего количества; обрыв запрещён.
Для программного профиля `closed-small-opening-transverse-translation/research-v1`
принята **поперечная проекция** отверстия относительно оси стержня. Это явная
консервативная формализация, не дополнительное подтверждение ширины от конструктора.

Обрабатываются только замкнутые прямоугольные отверстия. Наружные вырезы, край,
непрямоугольные отверстия и отверстия с поперечным размером от 300 мм не получают
разрешения обхода. Если один стержень пересекает и малое, и неподходящее отверстие,
он не допускается к сдвигу по этому правилу. Материал — пересечение всех сечений
фактического Solid: высота укладки не угадывается, уступы не заполняются.

Все исходные владельцы стержня сохраняются; сдвиг должен оставаться внутри **всех**
его исходных зон. Диаметр, класс, длина, количество и соответствующий инвентарь
раскроя неизменны. Продольный перенос разрешается только в свободном запасе той же
длины с полными 40d нового диаметра за каждым обязательным интервалом. Касание
фона в схемах СТО не теряется и проникновение в него не разрешается.

Сохранённого количества недостаточно для покрытия. Сервис восстанавливает
конечные области обслуживания из исходного периодического шаблона СТО: например,
для условного @150 это чередующиеся полуширины 100/50 и 50/100, не 75/75.
При сдвиге области переносятся, **но не расширяются** до новых соседей; вклад
нескольких недостаточных зон не суммируется. Все исходные полигоны КЭ проверяются
по геометрическому объединению достаточных областей без удаления спроса над отверстиями.
Это всё ещё исследовательская аппроксимация обслуживания, не расчёт прочности.

## Совместный поиск и независимая проверка

`optimization/algorithms/opening_relocation.py` строит конечные варианты положения
целых стержней; MILP выбирает ровно один вариант на стержень. Геометрические атомы
покрытия учитывают границы всех предложенных областей и точные пересечения с КЭ,
не только центры КЭ. Ограничения несовместимых пар запрещают пересечение тел одного
направления. Уже существующая нерешённая пара сохраняется только при неизменности
обоих стержней; перенос не может прикрыться прежним ID конфликта.

`optimization/services/opening_relocation.py` повторно проверяет весь комплект
без доверия матрице и флагам решателя: идентичность инвентаря, полные 40d, фон,
владельцев, зоны, геометрию host, пары тел и исходное покрытие. Поиск ограничен;
ошибка проверочного бюджета не превращается в разрешение частичного результата.
Не найденные сдвиги остаются в полной раскладке с прежними причинами.

`application/opening_relocation.py` заново восстанавливает исходные составные зоны
на свежей карте DXF и проверяет прежний полный физический пакет. Старые сертификаты
неизменных поперечных осей не подделываются: выход имеет отдельную схему
`physical-bar-relocation-draft/v1`, а review — `small-opening-relocation-review/v1`.
Новый черновик предназначен для отдельного **графического просмотра**, не для
загрузки в legacy `Physical Plan Trial` и не для структурного размещения Rebar.

## Реальная серия на неизменных исходниках

Вход: `artifacts/revit_delivery_2026_09_14/host-aware-v1`, snapshot плиты над 3-м
этажом `k09-typical-3-14-plate-11700.json`, кандидат `plate:52`, host-report `122250`.
Все четыре DXF перечитаны; исходный спрос 1636 КЭ по направлениям сохранён.
Привязка XY=0 относится к проверенному снимку, не к актуальной открытой модели.

Из 406 исходно не помещавшихся в общий контур стержней:

- 254 затрагивают наружный контур;
- 139 затрагивают отверстие с поперечной шириной от 300 мм;
- 13 допущены к поиску обхода малых отверстий.

| Лимит вариантов на стержень | Сгенерировано | После лимита и фиксированных коллизий | Сдвинуто | Осталось host-нарушений |
| --- | ---: | ---: | ---: | ---: |
| 32 | 834 | 264, включая исходные положения | 1 | 405 |
| 128 | 834 | 544, включая исходные положения | 1 | 405 |

В первом опыте лимит затронул 10 стержней, отбрасывание фиксированных коллизий —
81 вариант; во втором — 1 стержень и 302 варианта. MILP завершён оптимально внутри
соответствующего конечного пула, не во всём пространстве возможных раскладок.
Увеличение бюджета здесь улучшения результата не дало.

Отдельная диагностика всех 13 допущенных стержней при лимите 128 показала:

- у всех 13 есть геометрически помещающиеся варианты с допустимым отношением к фону;
- у 2 все предложенные варианты пересекают фиксированные стержни;
- из оставшихся 11 только у 1 есть сдвиг, сохраняющий покрытие при неизменности
  остальных стержней (15 вариантов, минимальный сдвиг 80 мм);
- у остальных 10 отдельный сдвиг теряет часть исходного покрытия. Это не запрет
  любого совместного перераспределения: совместная проверка выполняется MILP.

Совместный поиск всех выбранных переменных также оставил один сдвиг. Полный
перечень с ID и счётчиками записан в
`artifacts/small_opening_delivery_2026_09_14/eligible-diagnosis.json`. Ограничение
128 отсекло только один из 129 вариантов одного стержня; это всё равно конечный
пул, не глобальный сертификат. Два неустранимых в пуле фиксированных конфликта:
`bottom-X/source-recovery-8/0/9` и `top-X/source-recovery-33/0/9`.

В обоих опытах принят один и тот же сдвиг: `bottom-X`,
`source-recovery-10/0/6`, Y=9100 → 9020 мм; продольный интервал не изменён.
Отверстие: X=9750..10250, Y=9050..9340 мм (поперечная ширина 290 мм).

Сохранились **902 физических стержня / 2989,953486 кг / 139 исходных зон /
25 прямых типоразмеров / 1196 исходных владельцев**. Пары пересечений одного
направления: **12 → 12**, новых 0; у перенесённого стержня конфликтов нет.
Полные 40d, фоновые контакты и модель неизменной партии раскроя проходят;
пропусков исходного спроса в названной модели покрытия 0. Это не означает, что
405 host-нарушений закрыты или что раскладка пригодна к выпуску.

Предварительные 179 геометрически возможных независимых переносов относились
к более широкой диагностике без этого набора совместных правил. Их нельзя выдавать
за количество реализованных исправлений: результат этой строгой итерации — **1**.

## Воспроизведение

```bash
PYTHONPATH=src python scripts/correct_small_openings.py \
  --pipeline-dir artifacts/revit_delivery_2026_09_14/host-aware-v1 \
  --snapshot artifacts/assistant_recovery_stock_2026_09_13/k09-typical-3-14-plate-11700.json \
  --candidate-id plate:52 \
  --working-host-report qmonitoring-working-host-20260914-122250-368000.json \
  --host-offset-x-mm 0 --host-offset-y-mm 0 \
  --host-binding-source 'Recorded 122250 snapshot: identity XY; all 1987 source FE match CAD; not live binding' \
  --maximum-candidates-per-bar 128 \
  --output-dir artifacts/small_opening_delivery_2026_09_14/new-run
```

Скрипт требует новый каталог, сверяет исходные DXF/PDF/snapshot, цепочку SHA256
физической выдачи, host и явную привязку до/после вычислений. Изменение кода во
время запуска блокирует запись. Старые JSON/RVT/ZIP не перезаписываются.
Результат: `physical-bar-relocation-draft.json`, `opening-relocation-review.json`,
человеческий `RESULT.md`. Exit 2 при сохранённых host-нарушениях или коллизиях —
ожидаемый диагностический исход, а не сигнал пройденной инженерской приёмки.

## Что остаётся непроверенным

Фактические Z и X/Y-коллизии в 3D, существующая арматура рабочей модели,
инженерное принятие модели обслуживания, новое чтение созданных объектов в Revit,
постоянное размещение и выпуск. Во всех новых результатах `placement_eligible=false`.
Ни ограничения анкеровки/расхода, ни запрет скрытого удаления спроса не ослаблены.
Загибы не добавлены.

## Дополнительный опыт: перестановка длин в той же партии

`scripts/experiment_host_trim.py` исследует остаточные 405 нарушений без изменения
исходных осей, всех владельцев и их прежних required-интервалов с полными 40d.
Сначала проверяются все более короткие каталоговые длины и точные интервалы их
положений внутри тела host. Затем проверяется обмен двух существующих длин при
совпадении класса стали и диаметра: укороченный стержень и удлинённый донор должны
помещаться в host и не участвовать ни в одной коллизии того же направления.

Из 405 стержней только **один** допускает такое укорачивание: `bottom-X`,
`genetic-13/0/2`, Ø10, 8775 мм; минимальный старый required-интервал с 40d —
6798,25 мм. Допустимы 6825 и 7800 мм, но ни одна из них не делит 11700 нацело.
Самостоятельная замена на 6825 мм оставляет остаток 1950 мм в полной партии:
2988,751311 кг и 404 host-нарушения — **не принятый вариант раскроя**.

Найдена и независимо перепроверена другая ветвь — обмен длинами:

- `bottom-X/genetic-13/0/2`: 8775 → 7800 мм,
  интервал −231,444..8543,556 → 25..7825 мм;
- `bottom-X/genetic-15/0/1`: 7800 → 8775 мм,
  интервал 549,638..8349,638 → 549,638..9324,638 мм.

Вся партия **902 стержня / 2989,953486 кг** и полный набор
«сталь / диаметр / длина / количество» сохранены, раскрой проходит.
Полное покрытие исходного спроса и прежние 40d проходят. Host-нарушения:
**405 → 404**; пары одного направления: **12 → 12**, новых 0,
у обоих изменённых стержней пар нет. Это первый найденный проверенный вариант
обмена, а не доказанный оптимум. Простая перестановка длины не решает остальные
404 нарушения. Ни часть плиты, ни непокрытый спрос из проверки не удаляются.

Результат этого опыта — отдельный исследовательский JSON, не экспорт для создания
Revit-арматуры. Проверка полного покрытия не подтверждает фактические Z, коллизии
X/Y в 3D, существующую арматуру модели или инженерное принятие конструкции.
Исходные source-сертификаты, предыдущие отчёты и RVT остаются неизменными.

Воспроизведение после указанного выше запуска коррекции:

```bash
PYTHONPATH=src python scripts/experiment_host_trim.py \
  --pipeline-dir artifacts/revit_delivery_2026_09_14/host-aware-v1 \
  --snapshot artifacts/assistant_recovery_stock_2026_09_13/k09-typical-3-14-plate-11700.json \
  --candidate-id plate:52 \
  --working-host-report qmonitoring-working-host-20260914-122250-368000.json \
  --relocation-draft artifacts/small_opening_delivery_2026_09_14/new-run/physical-bar-relocation-draft.json \
  --relocation-review artifacts/small_opening_delivery_2026_09_14/new-run/opening-relocation-review.json \
  --output artifacts/host_trim_2026_09_14/new-run.json
```

Верхний уровень JSON описывает **небалансированное** отдельное укорачивание.
Подтверждённая перестановка находится в `stock_preserving_exchange.accepted`;
её показатели нельзя смешивать с первой ветвью. CLI отдельно подписывает обе ветви.
