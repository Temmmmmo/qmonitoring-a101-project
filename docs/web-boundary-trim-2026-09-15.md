# Web: зоны, стержни и обрезка по контуру и отверстиям

## Последующий этап: удаление резервных отрезков

После обрезки по отверстиям web теперь отдельно удаляет только избыточные
отрезки, не теряя ранее покрытой геометрии исходных КЭ ни по наличию стали,
ни по контролю 40d. Реальная партия: **1135 → 975 стержней**, масса
**2761,061677 → 2641,403648 кг**, позиции **292 → 231**; изополя и 139 исходных
зон неизменны. Пробелы покрытия **159 / 381**, **12** оставшихся 3D-пар и
непройденный безотходный раскрой остаются явно видны. Это не инженерный pass.

Для новой партии скачивается `graphic-bar-plan-pruned/v1` с полным предыдущим
trim-пакетом и списком оставленных ID. Старая схема ниже описывает историю
**до cleanup** и не переиспользуется для неполного набора отрезков.
Контракт, проверки и артефакт: [trimmed-length-cleanup-2026-09-15.md](trimmed-length-cleanup-2026-09-15.md).

## Актуальное поведение — последующее указание 15 сентября

Пользователь дополнительно разрешил **обрезать стержни в отверстиях**. Теперь в
`/composite` режим называется «Обрезать по границе плиты и отверстиям»: выберите
Working Host JSON и подтвердите совпадение XY. Четыре оригинальных DXF уже выбраны.
Новый расчёт сохраняет реальные внутренние кольца во всех пересекаемых высотных
сечениях. В материале плиты остаются отдельные физические отрезки с новыми длинами,
массой и позициями. Защитный слой к границе реза **не добавляется**.

Исходные КЭ не вырезаются вместе с отверстиями: наличие стали и контроль40d
перепроверяются на всей исходной потребности. Каждый исходный ID имеет one-to-many
или one-to-zero mapping; `removed_input_bars` содержит все пустые пересечения,
`removed_wholly_external_bars` — только внешние. Старый внешний-only режим ядра
сохраняется как `respect_openings=False`, новый веб-режим использует `True`.

По умолчанию вид **«Зоны + стержни»** показывает охристые исходные прямоугольники Z
и синие фактические оси в одной системе координат, размеры/диаметр/шаг при наведении
и параметры в таблице. Исходные прямоугольники не заменяются bbox обрезанных стержней:
это разные стадии. Можно отдельно показать изополя с зонами или только стержни.
Режимы отображения не меняют ведомость, геометрию или результаты проверок.

Plan Preview **0.2.2** принимает новый openings-вариант графического JSON с отдельными
статусами отверстий и материала, сохраняя поддержку старых пакетов. Код-only ZIP
доступен в `/revit`, данные модели в него не включены. Это графика, не Rebar;
запуск именно0.2.2 в настоящем Revit ещё требуется.

## История: предыдущий режим без учёта отверстий

В `/composite` у комплекта К09 есть отдельный режим **«Укоротить стержни по настоящей границе плиты»**.
Обычный запуск К09, пользовательская загрузка четырёх DXF и исходное отображение зон не заменены.

Для нового запуска нужен JSON Working Host с полной поддержанной геометрией Solid и явное
подтверждение совпадения XY этих DXF и выбранной плиты. Смещение, поворот и масштаб автоматически
не подбираются; прямоугольник изополя не подставляется вместо границы. Форма принимает до 32 MiB,
отклоняет дубли полей, повреждённую геометрию и отсутствие подтверждения до расчёта.

Каждый запуск заново читает четыре оригинальных DXF с проверкой SHA256 и проходит существующую
физическую нормализацию. Это **самостоятельная прямая web-партия**, а не результат отдельного
офлайн-поиска с П-образными стержнями, обменом длин и дополнительными высотами.

После этого прямые стержни действительно укорачиваются/разделяются по внешнему контуру во всех
пересекаемых высотных сечениях. Проверяется полная ширина тела. Замкнутые проёмы и защитный слой
исключены из этой операции по выбранной политике; внешние вырезы сохранены. Если исходное тело
не имеет пересечения, проверяется разрешённый сдвиг поперечной оси на один радиус внутрь с
сохранением исходного окна и проверкой фона. При всё ещё пустом пересечении не остаётся ни одного
отрезка: исходный ID сохраняется в `piece_mapping` с `piece_ids=[]` и обязательном
`removed_wholly_external_bars`. Это изменение физического результата, **не удаление исходных КЭ**.

Высоты — явный `ResearchLayerProfile`: X ближе к обеим граням, Y отступает внутрь на 16 мм.
Он не выдан за измеренные положения существующей арматуры или согласованный Revit-профиль.
Проверки исходных КЭ, прежнего контроля 40d, всей новой партии, 3D-пересечений добавок и раскроя
выполняются заново. **Геометрическое наличие стали не доказывает анкеровку.** Существующий фон
в Revit и инженерная пригодность не подтверждены. Старый физический rollback-пакет удалён
из нового представления, а не дополнен изменёнными длинами под прежним сертификатом.

На странице исходные изополя и прямоугольные зоны выбраны по умолчанию и не изменяются.
Переключение на физические стержни показывает новые реальные концы, внешний контур host и
все оставшиеся нарушения без дополнительной маски рисунка. Масса, число стержней, позиции
и ведомость относятся к этой же новой партии. Непокрытые КЭ по наличию стали и с 40d подписаны
раздельно; сохранение входа не называется полным покрытием.

Кнопка скачивания раскладки выдаёт `graphic-bar-plan-draft/v1` для графического предпросмотра
Revit, а не команду создания арматуры. В нём отдельно сохранены before/after, все исходные ID,
длины, явные сдвиги осей и карта физических отрезков. Обязательные сводки внешнего остатка и
3D-пар не подменяются тремя проверками наличия/40d/раскроя. Для полностью пустого результата
остаётся отчёт с исходным спросом и отказами, но графический экспорт отключён.

Воспроизводимый реальный smoke: `artifacts/source_views_2026_09_15/run_boundary_trim_web_smoke.py`;
результаты сохраняются в новые каталоги без перезаписи, с хешами входного host, кода и выходов.
Исходные частные DXF и RVT не добавляются в Git. Актуальные численные результаты следует брать
из последней `summary.json`, не смешивая их с офлайн-партией с гнутыми стержнями.
