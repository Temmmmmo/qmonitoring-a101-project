# Revit MVP — кодовые расширения и передача специалисту

Дата: 15 сентября 2026. Revit 2024, установленный pyRevit, IronPython 2.7.
Эти архивы содержат **только код/инструкции/manifest**; RVT, RFA, DXF и расчётные
JSON нужно получать отдельно. Живой Revit-run новых режимов не выполнен.

## Основной путь: расчёт на сайте → Plan Preview

1. На сайте рассчитай одно направление или комплект плиты. Проверь факт/норматив,
   `fail` и `not_checked`; не считай графическую выдачу разрешением размещения.
2. Скачай совместимый `source-isofields-zones/v1` для исходных изополей/зон либо
   отдельный `graphic-bar-plan-draft/v1` / `graphic-bar-plan-pruned/v1` для прямых
   обрезанных/оставленных стержней. Общий composite JSON напрямую не подходит.
3. Установи [Plan Preview ZIP](downloads/qmonitoring-plan-preview-0.2.3-code-only.zip):
   распакуй в **новую** папку, добавь в pyRevit Custom Extension Directories её
   родительский путь, внутри которого `QMonitoringPreview.extension`, нажми Reload.
   Старые расширения и worksets не удаляй.
4. На локальном/отсоединённом рабочем RVT выбери native Floor, нажми
   `QMonitoringPreview → Diagnostics → Plan Preview`, выбери JSON и **известный**
   XY-сдвиг. Ноль допустим только при совпадении начал. Подтверди новые виды.
5. Сохрани отдельный JSON-отчёт, сделай скриншоты и передай конструктору вместе
   с исходными статусами. Плагин не вызывает Save/Sync и не создаёт Rebar.

Для реального pruned-экспорта проверены точный SHA исходного trim JSON, полная
карта 1135 входных ID, уникальные 975 оставленных ID, буквально неизменная
геометрия выбранных отрезков и поячейковая nonregression-запись FE-покрытия.
Разница площади 3e-11 мм² — машинный шум; transport допускает максимум 1e-8 мм²
при том же FE ID/статусе и обязательном пустом `previously_covered_geometry_lost`
независимого checker. Это не повторная проверка покрытия в текущем RVT:
`coverage=fail`, `40d=fail`, `stock=fail` остаются видимыми. Выход 975 физических
стержней / 231 позиция / 2641,403648 кг — не инженерное подтверждение.
3D-статус также сверяется с полным списком пар: счётчики должны совпадать,
каждый endpoint обязан быть оставленным ID. Нулевой список без полного backend
доказательства и полного фонового инвентаря выводится как `not_checked`, не `pass`.

Flat MVP S1 использует **внешний контур DXF** и не учитывает отверстия, перепады
высоты или защитный слой; это не измеренный Revit-host. Его 40d/coverage/stock
также остаются `fail`. Проверять XY и реальную модель нужно отдельно.

## Альтернатива: Source Workflow 8.1

[Source Workflow ZIP](downloads/qmonitoring-source-workflow-0.1.1-code-only.zip)
устанавливается рядом, в отдельную `QMonitoringWorkflow.extension`, панель
`Workflow`. На текущем горизонтальном плане выбери направление, один исходный
DXF, SHK либо явный mapping, настройки. Укажи доверенный HTTPS-сервер (HTTP только
localhost) и **отдельно подтверди upload**. Ответ нового анализа привязан SHA к
точному запросу и исходным байтам. Затем выбери **уже загруженные** семейства
элементов узлов/аннотаций, реальные параметры экземпляра и подтверди вставку
исходных зон на текущем виде. Readback сверяет экземпляры, ошибка откатывает
группу. Это не конструктивный Rebar, не 3D-семейство и не пройденный полный ТЗ.
Первый настоящий Revit-прогон Workflow всё ещё требуется.

Оба ZIP детерминированы и имеют `manifest.json` с SHA256 каждого файла. Кодовые
зависимости, версии и whitelist проверены offline-тестами; package не содержит
исходные данные проекта. После первого Revit-запуска пришли JSON, полный traceback
при ошибке, снимки текущего вида и использованные версии расширений.
