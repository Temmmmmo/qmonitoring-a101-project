# QMonitoring в pyRevit — 0.3.0

Это три тестовые кнопки, не автоматическое армирование плиты:

- **Reference Probe** — только чтение модели и сохранение JSON, без транзакций.
- **Creation Trial** — временное создание одного Rebar-набора, чтение фактических
  осей и **обязательный откат**, в том числе при успехе. Стержни в модели не остаются.
- **JSON Trial** — параметры одного набора из JSON, внутренний Commit, повторное
  чтение осей и **обязательный откат внешней группы**. Это следующий запуск.

Ни одна кнопка не сохраняет RVT и не отправляет данные по сети. Creation Trial не
не вызывает Commit; JSON Trial вызывает его только внутри группы с обязательным
откатом. Переключателя «оставить результат» нет ни у одной кнопки.

Цель: Revit **2024.3.4**, уже установленный pyRevit со стандартным IronPython-движком.
Устанавливать Python, библиотеки проекта, Dynamo или сервер не требуется.
Подтверждён движок специалиста: **IronPython 2.7.12**. В 0.1.1 исправлено чтение
`Element.Name`; повторный запуск дошёл до сериализации JSON и выявил ошибку ASCII
на кириллице в сочетании с символами единиц (например, `см²`). В **0.1.2** JSON
формируется как Unicode и явно кодируется в UTF-8. Переименовывать файлы, элементы
или Windows-папки в латиницу не нужно.

Первый реальный JSON из Revit получен 7 сентября: сбор завершён без ошибок,
все девять стержней прочитаны. В 0.2.0 также исправлено ложное `differs`: запрошенные
100 мм читаются из родительской AreaReinforcement; дочерний RebarInSystem возвращает
96,875 мм. Числа модели менять не нужно, старый JSON повторно присылать не требуется.
Реальный повтор 0.2.0 подтвердил `collected / matches / 0 issues`. Creation Trial
прошёл чтение эталона и проверку solid, но остановился **до транзакции**: bbox-фильтр
поймал Sketch 407800 и общий Element 407864 с именем `{3D}`. Категория второго в старом
JSON отсутствует, поэтому по имени нельзя утверждать, что это рамка 3D-вида.
В 0.2.1 служебные элементы распознаются по API, а не по имени/запомненному ID.
Отчёт 0.2.1 от 8 сентября подтвердил: эскиз уже исключается корректно, а `{3D}`
оказался **камерой вида** — `OST_Cameras`, ID категории −2000500, CategoryType=Model.
Это не Section Box и не физическое оборудование. В 0.2.2 добавлено узкое исключение
для этой встроенной категории; другие Model-категории и неизвестные объекты остаются
блокирующими. В запуске 0.2.1 транзакция не начиналась, стержни не создавались.
Реальный запуск **0.2.2** от 8 сентября подтвердил создание, чтение всех девяти осей
и откат: `passed_rolled_back`, все 55 проверок совпали. Эталон и состав ID восстановлены.
**JSON Trial 0.3.0 проверен локально; реальный запуск после Commit ещё ожидается.**

## Обновление с 0.1.x / 0.2.x

Закрой Revit. Распакуй новый ZIP и замени папку `QMonitoring.extension` в том же
каталоге, который уже подключён в настройках pyRevit. Не создавай дополнительную
вложенную `.extension` и не подключай одновременно старую и новую копии.
Затем открой Revit заново. Менять настройки модели, устанавливать
другой движок или переподключать путь расширения не нужно, если он остался прежним.

В начале журнала теперь печатаются версия кнопки и Python. Должно быть
`QMonitoring JSON Trial 0.3.0` (у остальных кнопок версия тоже 0.3.0).
Если осталась другая версия, используется старая копия
или закэшированный модуль; проверь каталог и полностью перезапусти Revit.

## Как установить и запустить Reference Probe

1. Распакуй переданный ZIP в отдельную папку, например `C:\QMonitoringProbe`.
   Внутри должны лежать `README.md`, папки `QMonitoring.extension` и `samples`.
2. В настройках pyRevit (`Settings`) добавь `C:\QMonitoringProbe` в список папок
   пользовательских расширений (`Custom Extension Directories` / аналогичный пункт
   в твоей версии). Добавляется **родительская папка**, не сама `.extension`.
   Нажми `Save & Reload` либо перезапусти Revit. Другие расширения удалять не нужно.
3. Открой **копию** `AR_MVP_R24_3_4_REFERENCE_v01.rvt` в Revit 2024.3.4.
   Не обновляй модель в более новый Revit ради теста.
4. На вкладке `QMonitoring`, панели `Diagnostics` нажми `Reference Probe`.
   Подтверди чтение текущей модели. Выделять плиту и стержни заранее не нужно.
5. Выбери CAD-экземпляр `Верхнее армирование вдоль ОСИ Х.dxf` из списка.
   Скрипт явно показывает ID и вид размещения: связь или импорт.
   В переданной модели для первого повторного теста выбери **связь `407861`**;
   импорт `407797` можно проверить отдельным вторым запуском. Удалять, переимпортировать
   или перепривязывать CAD ради этой ошибки не нужно.
   Если CAD отсутствует, всё равно получится частичный отчёт по плите и арматуре.
6. Сохрани предлагаемый **новый** файл `qmonitoring-reference-….json` и пришли его мне.
   Существующие файлы скрипт не перезаписывает. Сохранять RVT после запуска не нужно.

Если кнопка не появилась, пришли скриншот настройки папки расширений и версию pyRevit.
Если появилась ошибка, пришли текст из окна pyRevit. Никакие типы арматуры или настройки
модели для обхода ошибки менять не нужно. Статус `partial` — тоже полезный результат:
пришли JSON, в нём указано, что именно не удалось прочитать.

Отчёт содержит геометрию, координаты, названия и идентификаторы элементов. Передавай
его по согласованному рабочему каналу, не публикуй в открытом репозитории. Скрипт не
добавляет пути RVT/DXF или имя Windows-пользователя специально, но названия элементов
и сообщения об ошибках могут содержать данные проекта.

## Следующий запуск: JSON Trial

1. Обнови расширение и полностью перезапусти Revit. Открой тестовую **копию** модели.
2. Нажми `QMonitoring → Diagnostics → JSON Trial`.
3. Выбери `samples/single-zone-trial.json` из нового ZIP. Это входные параметры,
   **не** JSON предыдущего отчёта. Для первого запуска ничего в нём не меняй.
4. Подтверди работу на копии и параметры: 9 × Ø25, 3900 мм, шаг 96,875 мм.
5. Выбери новый `qmonitoring-json-trial-….json` для результата и дождись завершения.
6. Пришли этот JSON и скриншот окна **JSON Trial**. Сохранять RVT не нужно;
   после отката временные стержни не видны — это ожидаемо.

Ожидаемый результат: `passed_rolled_back`, Commit `committed`, сверка после Commit
`matches`, откат группы `rolled_back`, восстановление `True`. Ошибка или другой
статус — тоже полезный отчёт; не меняй модель для обхода проверки.

Этот режим использует все проверки эталона, solid, cover и свободного участка,
описанные ниже. Внешняя TransactionGroup открывается **до** внутренней Transaction.
После успешной сверки временных осей выполняется Commit, затем Rebar заново получается
по ID и его фактические оси перечитываются. В `finally` группа всегда откатывается.
Отдельно сверяются состав ID экземпляров/типов и снимок host/ручного эталона.

Новые предупреждения и ошибки в обработчике Commit записываются в `commit_failures`
и приводят к отказу от Commit. Скрипт не исправляет их и не удаляет предупреждения
из существующей модели; `SetClearAfterRollback` очищает сообщения отменённого теста.
Включена синхронная модальная обработка. Если API всё же вернёт Pending или откат
не подтверждён, успех не заявляется и дальнейшее чтение модели не выполняется.
**При `rollback_unconfirmed` или `restoration_failed` не сохраняй копию; пришли
отчёт и журнал, затем закрой её без сохранения.**

Вход `qmonitoring-single-zone-trial/v1` — отдельный ограниченный контракт API-теста,
не экспорт оптимизатора `plate-solution-revit/v1` / `reinforcement-zone-revit/v2`.
Поддерживается только Top X, host 407801, тип 165163 с обоими диаметрами 25 мм,
NumberWithSpacing, без крюков и дополнительных выпусков. Допускаются 2–32 стержня,
длина 100–6000 мм, точный равномерный шаг 25–300 мм. Смещение первой оси задаётся от
минимальных X/Y host-bbox по **внутренним** осям Revit, не от shared origin или DXF.
Z вычисляется из верхней грани, cover и модельного радиуса. Тело всех стержней должно
поместиться с защитным слоем; обрезания и автопереноса нет.

JSON UTF-8 (BOM допускается), не более 16 KiB. Лишние/пропущенные/повторные поля,
NaN/Infinity, неверные единицы, строковые числа и логические значения вместо чисел
отклоняются до транзакций. Обязательное `placement_eligible=false` нельзя переключить
для обхода гейтов. Условный шаг @150 (100/200) и составные наборы этот тест не реализует.

## Уже пройденный тест: Creation Trial (без Commit)

1. Открой **ту же тестовую копию** модели, из которой получен успешный JSON.
   Совместные модели, другой Revit, редактор семейств и открытая транзакция отклоняются.
2. Нажми `QMonitoring → Diagnostics → Creation Trial` и подтверди работу на копии.
   Повторно выбирать CAD или запускать Reference Probe перед этим не нужно:
   эталон и плита считываются новой кнопкой самостоятельно.
3. Выбери новый файл `qmonitoring-creation-trial-….json`. Отмена диалога, существующий
   файл или расширение не `.json` останавливают запуск **до транзакции**.
4. Дождись результата. Пришли JSON и скриншот **окна результата pyRevit**.
   После завершения стержней теста не видно в модели — это ожидаемый обязательный откат.
   RVT сохранять не нужно, снимок временных стержней сейчас не требуется.

Тестовый участок начинается на 1000 мм по внутренним X/Y от минимального угла плиты.
В переданной копии ожидаются оси `x=1000…4900`, `y=1012,5…1787,5`, `z=−37,5` мм:
9 стержней Ø25 длиной 3900 мм с равномерным шагом 96,875 мм, без крюков.
Высота выводится из верхней грани и cover, а не копируется из DXF.
Обычный Rebar использует NumberWithSpacing; новую AreaReinforcement не создаём.
Это воспроизведение уже измеренной геометрии, не решение вопроса «точный шаг 100»
для алгоритма. Повторные выпуски 40d не добавляются к фактическим 3900 мм.

Перед созданием принимается только целая прямоугольная горизонтальная плита с одним
шестигранным solid, размерами 23600 × 14000 × 300 и cover 25 мм. Проёмы, кривые грани,
скосы, дополнительные solids, вложенная геометрия и несовпадение объёма блокируют тест.
Пространство участка резервируется на всю толщину плиты с запасом 100 мм.
Из кандидатов исключаются сама плита, CAD, аннотации и определения видов; эскиз —
только при совпадении `Floor.SketchId` и обратного `Sketch.OwnerId`; рамка 3D-вида —
только по точной категории `OST_SectionBox`; камера вида — по `OST_Cameras`.
Физическое оборудование (например, видеокамера семейства Security Devices) под это
исключение не попадает. Имена `{3D}` / «Эскиз» / «Камеры», известные ID,
все внутренние категории или все чужие эскизы не являются основанием для исключения.
Неизвестные элементы и физические объекты блокируют запуск. Связанные RVT также
требуют отдельной проверки и блокируются.
В `obstacle_check.ignored` сохраняются исключения с причинами, а `obstacles` содержит
блокирующие объекты. Для обоих списков добавлены категория, bbox и OwnerViewId;
неудачное чтение этих сведений отражается явно, не превращая неизвестный объект в свободное место.
Это консервативный локальный фильтр: он может остановиться на объекте, который не
стал бы реальной коллизией. Не удаляй препятствия ради обхода проверки — пришли отчёт.

В одной транзакции создаётся набор (и при необходимости временная форма), выполняется
Regenerate, считываются все оси и проверяются абсолютные координаты обоих концов,
длины, число, диаметры, host, тип, правило раскладки и отсутствие крюков. Затем всегда
RollBack. Проверяются оба статуса отката, прежний состав ID экземпляров/типов и
неизменность прочитанных данных плиты и ручного эталона.

Возможные статусы:

- `passed_rolled_back` — геометрия совпала, откат и восстановление проверены.
- `blocked_preflight` — остановка до создания, причина и найденные препятствия в JSON.
- `failed_rolled_back` — ошибка API/чтения или несовпадение геометрии, откат подтверждён.
- `rollback_unconfirmed` / `restoration_failed` — **не сохраняй копию**, пришли JSON
  и журнал, затем закрой её без сохранения. Не повторяй запуск в сомнительном состоянии.

Creation Trial намеренно не вызывает Commit: его успешный результат не проверяет commit-time
обработку ошибок Revit. Это не выдача армирования, не проверка всей плиты и не снятие
`placement_eligible=false`. Фазы фоновой сетки и порядок X/Y не назначаются.

## Что читается Reference Probe

- Версия/сборка Revit, версия Python-движка, название и совместность документа.
- Плита `407801` с Mark `TEST_SLAB_01`: тип, уровень, габарит, верхние/нижние грани
  со всеми контурами рёбер, защитные слои сверху/снизу/остальные.
- AreaReinforcement `407878` с Mark `AR_TEST_TOP_X_001`: host, граничные кривые,
  встроенные параметры, связанные `RebarInSystem`.
- Все существующие позиции стержней этой области: фактические кривые осей, длины,
  номинальный/модельный диаметры, заданный максимальный шаг. Исключённые позиции
  не считаются стержнями; индивидуальное смещение учитывает Revit API.
- Числовая сверка ручного эталона: 3900 × 800 по границе, девять Ø25 длиной 3900,
  максимальный шаг 100, фактические интервалы 96,875, крайние оси через 775,
  боковые отступы осей 12,5 мм. Допуск сверки — 0,1 мм.
- Расстояние осей/тел стержней до плоскостей верхней и нижней граней — только для
  случая одной горизонтальной плоской грани с каждой стороны.
- Выбранный CAD: тип, ID, импорт/связь, состояние связи, габарит и обе матрицы
  `GetTransform` / `GetTotalTransform`. Сам исходный DXF не открывается и не пересвязывается.
- Известные типы арматуры `165160`, `165161`, `165163`.

ID проверяются вместе с классом и Mark. Если открыта другая модель или эталон
пересоздан, скрипт не подбирает похожие элементы молча: запишет проблему в отчёт.

## Как понимать результат

`status=collected` означает, что чтение завершилось без зарегистрированных ошибок,
а не что модель соответствует эталону. Числовая сверка находится отдельно:
`area.reference_comparison.status = matches / differs / not_checked`.
Если часть позиций не удалось прочитать, итоговое число физических стержней — `null`,
а не число успешно прочитанных записей. Нерегулярная форма не подменяется прямоугольником.

Геометрия отчёта — миллиметры в системе **внутреннего начала Revit**, не координаты
ЛИРА/DXF или общие координаты проекта. Базис матриц безразмерный, начало — в мм.
Сырые параметры `value_internal` сохраняют собственные внутренние единицы Revit;
`length_mm` добавляется только параметрам с типом данных Length.

JSON записывается в UTF-8 без BOM и без потери символов. Числа, `null` и логические
значения не превращаются в строки. `NaN`, бесконечность и неподдерживаемые объекты
остаются ошибками; сериализация выполняется до создания файла, поэтому её сбой
не оставляет пустой JSON.

Контуры граней включают внутренние петли, но скрипт не классифицирует их как проёмы
и не проверяет попадание стержня внутрь бетона. Расстояние до бесконечной плоскости
грани не является проверкой защитного слоя у края/проёма. Порядок X/Y и фаза фоновой
сетки не назначаются и не восстанавливаются из отсутствующих данных.

Матрица CAD сама по себе **не подтверждает** масштаб и соответствие сырым координатам
DXF. После первого отчёта нужна сверка с исходным DXF по контрольным точкам/размерам.
Чтение текущей связи также не доказывает её переносимость на другой компьютер.

Во всех отчётах `placement_eligible=false`. Даже полное совпадение чисел не проверяет
покрытие составной схемой, порядок слоёв, коллизии и инженерную допустимость.
Скрипт не добавляет `40d` повторно к прочитанной фактической длине 3900 мм.

## Для разработчика

Сборка ZIP из checkout (без RVT, DXF, исходных материалов и зависимостей):

```bash
python3 scripts/package_revit_probe.py
python3 -m pytest -q tests/integrations
python3 -m ruff check integrations/pyrevit scripts/package_revit_probe.py tests/integrations
python3 scripts/verify_revit_probe_runtime.py --lib-dir integrations/pyrevit/QMonitoring.extension/lib
```

ZIP создаётся в `artifacts/revit_probe/`; повторная сборка требует нового имени через
`--output`, существующий архив не перезаписывается. Внутри только фиксированный список
файлов расширения и эта инструкция. Код кнопки не импортирует Python-ядро проекта.

`scripts/verify_revit_probe_runtime.py` также запускается настоящим `ipy` версии 2.7.12
с флагом `--require-ironpython`. Он проверяет старый сбой, новый UTF-8 round-trip,
кириллические пути, запрет перезаписи и ошибочные значения; дополнительно компилирует
все восемь Python-файлов поставки и проверяет чистую геометрию Creation Trial,
загрузку JSON-примера и отказ на ошибочных входах.
