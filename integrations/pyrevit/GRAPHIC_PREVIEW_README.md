# Plan Preview 0.2.1 — исходные изополя, зоны и отдельная физическая схема

Revit 2024 / pyRevit / IronPython 2.7. **Графические элементы, не Rebar.**

## Новое: фактически укороченная прямая партия

Отдельный `graphic-bar-plan-draft/v1` показывает **реальные новые отрезки**, а не
визуально обрезанные старые линии. Выбери соответствующий JSON в той же кнопке.
Создаётся один новый вид с четырьмя разнесёнными направлениями; source-виды не меняются.

Вход содержит обе полные партии и соответствие каждого исходного ID всем его отрезкам.
Разделение увеличивает количество физических деталей; прежние масса/количество/позиции
не копируются. Плагин независимо сверяет полный состав, фактические длины, обе массы,
новые позиции, отсутствие потерянных родителей и перекрывающихся кусков одного стержня.
Если исходный стержень **целиком вне внешнего контура**, mapping может иметь ноль
отрезков только вместе с отдельной записью `removed_wholly_external_bars`: ID,
направление и причина. Полная исходная партия с геометрией и source owners остаётся
во входе и отчёте; заголовок явно считает такие удаления. Внешняя фиктивная линия
вместо пустого пересечения не оставляется. КЭ не удаляются, их проверки пересчитывает
backend. Полностью пустая итоговая партия также показывается явно как ноль, не как
успешная инженерная раскладка; отсутствие этих записей блокирует графический запуск.
Каждая новая длина — положительный подынтервал исходной. Исходные Ø, сталь и source IDs
сохраняются. При явном opt-in допускается только неизменная ось или сдвиг ровно ±D/2
(числовой допуск 0,000001 мм); все куски одного родителя имеют одну ось. Это **не**
проверка пригодности такого сдвига для конструкции — её выполняет отдельный backend.

Янтарным отмечаются сокращённые/сдвинутые отрезки, красным — native Solid/cover,
фиолетовым — вычисленные XY-пересечения добавок. Неудачные стержни не пропускаются.
Обязательный заголовок показывает **отдельно** геометрическое наличие без анкеровки,
40d, раскрой 11700, остаток по внешнему контуру и доказанные/неопределённые 3D-пары
из backend. `not_checked` и `None` означают «не проверено», не нулевые ошибки.
Эти backend-статусы в Revit не пересчитываются и не являются проверкой текущей модели.
Смена введённого XY явно помечается: статусы прежней привязки на этот вид не переносятся.

После Commit перечитывается **каждый** отрезок с исходным ID/индексом и допуском
0,01 мм, а также обязательный текст статусов. Ошибка — откат всего нового вида.
**U/дуги/гнутые детали и их масса не принимаются**: этот транспорт только для полных
прямых партий. Исследовательский набор с 54 U сюда отправлять нельзя, даже если
передать лишь проекции рабочих участков. Старые сертификаты 40d и физического v1
не подменяются; готовность к размещению всегда false.

Новый cut-режим 0.2.1 проверен локально; успешный запуск 0.1.1 с 902 линиями не является
подтверждением нового формата. Для 0.2.1 ещё нужен первый фактический Revit readback.

## Новый code-only архив: установка без удаления прежних инструментов

1. Распакуй архив в новую папку. В pyRevit → Settings → Custom Extension Directories
   добавь **родительскую папку**, внутри которой лежит `QMonitoringPreview.extension`.
   Старое `QMonitoring.extension` не отключай. Выполни Reload / перезапусти Revit.
2. Открой локальную рабочую модель или отсоединённую копию **с сохранёнными рабочими
   наборами**. Выдели одну native-плиту и нажми
   **QMonitoringPreview → Diagnostics → Plan Preview**. Прямое хранилище/cloud не поддержано.
3. Из приложения скачай отдельный `source-graphics.json` формата
   `source-isofields-zones/v1`. В архиве установки **нет** исходных RVT/DXF или частных отчётов.
   Выбери этот JSON, новое имя отчёта и известный сдвиг XY во внутренние координаты Revit.
   `0; 0` допустимо только при совпадении начал; масштаба/поворота плагин не угадывает.
4. Подтверди создание **четырёх новых чертёжных видов**: низ X/Y, верх X/Y.
   Откроется первый, остальные видны в диспетчере проекта как `QMonitoring SOURCE`.
   Пришли JSON и скриншот каждого нужного направления.

## Что показывает исходный режим

- Каждый исходный КЭ показан отдельной цветной FilledRegion, с исходными ID/уровнем/ACI.
- Синий прямоугольник — **пятно потребности `demand_bbox`**.
- Фиолетовый — **осевой envelope исходного дополнительного набора после 40d/раскроя**,
  `bar_axis_bbox_mm`, не граница AreaReinforcement. Набор из одной оси имеет линию,
  а не выдуманную ширину. Оси физических стержней в этом режиме не рисуются.
- Z1, Z2… ссылаются на исходный ID; рядом вынесены Ø, условный шаг, установленная длина,
  ширина окна, количество и фаза/схема. Полный неизменный zone draft записан в JSON-отчёт.
  Это **графическая разметка параметрических зон**, не редактируемое семейство арматуры.

Исходные зоны **не являются нормализованной физической партией**. Их число стержней,
оси и длины нельзя подменять итоговой физической ведомостью. Для физического плана
запусти ту же кнопку с отдельным `physical-bar-plan-trial/v1` или relocation draft:
он создаёт другой вид и не изменяет исходные четыре.

Ничего не отсекается по отверстиям, cover или границе. `source_bbox_mm` — рамка исходных
данных, **не восстановленный контур плиты**. Этот режим вообще не вычисляет ТЗ/host-гейты.
В старом физическом режиме красная native Solid/cover-диагностика также не равна новому
ТЗ-гейту `user-TZ-outer-boundary-no-openings-no-cover/2026-09-15-v1`.

## Безопасность и границы проверки

Только новые виды/их собственные аннотации; никаких изменений плиты, старых видов,
семейств или активного рабочего набора, Checkout/Save/Sync. Новые виды могут попасть
в хранилище при **последующей ручной синхронизации** пользователя.
Понадобятся существующие тип FilledRegion, Solid fill и TextNote: автоматически
создавать или менять типы плагин не будет.

После Commit перечитываются все четыре вида, все КЭ, рёбра обоих исходных envelope,
цвета и весь созданный текст; XY проверяется с допуском 0,01 мм. Масштаб вида 1:100
**не меняет координаты**: перевод только мм / 304,8. Отмена, неверный readback или ошибка
откатывает **всю группу четырёх видов**; неподтверждённый откат отдельно отражается в JSON.
Лимиты: JSON 32 МиБ; 12 000 КЭ; 1 000 зон; 80 000 вершин; 3–8 вершин на КЭ.
Короткая для Revit грань, некорректный полигон или превышение лимита останавливает
полный запуск без упрощения геометрии или частичной успешной выдачи.

SHA — запись происхождения, не проверка текущего RVT/DXF. Без SHA разрешён только
явно подписанный `unverified` графический просмотр. `placement_eligible=false` и
`engineering_approval=false` всегда. Новый FilledRegion-режим проверен локальными
дублями API; первый настоящий запуск 0.2.0 в Revit ещё нужен. Успешный живой readback
0.1.1 относится **только к прежним 902 графическим линиям**, не к этому новому режиму.

API сверено с первичными материалами Autodesk:
[FilledRegion.Create/GetBoundaries](https://blog.autodesk.io/create-a-filled-region-to-use-as-a-mask/comment-page-1/),
[Surface Pattern override отдельной области](https://www.autodesk.com/support/technical/article/caas/sfdcarticles/sfdcarticles/Revit-How-to-override-the-pattern-in-filled-regions.html),
[изменения API 2019.1](https://blog.autodesk.io/whats-new-in-the-revit-20191-api/),
[Text: управляющие символы абзацев](https://help.autodesk.com/cloudhelp/2024/ENU/Revit-API/files/Revit_API_Developers_Guide/Revit_Geometric_Elements/Annotation_Elements/Revit_API_Revit_API_Developers_Guide_Revit_Geometric_Elements_Annotation_Elements_Text_html.html).

## Прежний физический режим и старые case-архивы

Это **графический просмотр всей партии**, не создание арматуры: в Revit появится
один новый чертёжный вид с четырьмя схемами «низ X / низ Y / верх X / верх Y».
Показаны все стержни выбранного результата и контуры выделенной реальной плиты,
включая проёмы и высотные уступы. Ничего не обрезается ради красивой картинки.

Этот раздел описывает физический путь, проверенный в **0.1.1** и сохранённый в 0.2.0.

Исправлен полученный в настоящем Revit сбой IronPython 2.7.12 `MutableTuple`
при подсчёте статусов перед отрисовкой стержней. Вложенные генераторы заменены
явными циклами; такой же риск убран из проверки конечных точек после Commit.
Входной план, геометрические проверки и правила рабочих наборов не менялись.

## Как запустить

1. Установи обновлённую `QMonitoring.extension` из архива в ту же папку расширений.
   Не оставляй две копии расширения одновременно; перезапусти Revit.
2. Открой рабочую модель. Рабочие наборы **сохраняются**: удалять их не нужно.
   Для переданной тестовой модели без доступа к хранилищу А101: «Файл → Открыть →
   Отсоединить от хранилища → Сохранить рабочие наборы», затем запусти кнопку
   **до сохранения RVT**. Это не удаление наборов и не обращение к серверу А101.
   При сохранении отсоединённого RVT с наборами он становится новым хранилищем;
   прямой запуск в хранилище эта версия отклоняет. Обычная локальная копия Revit
   с сохранённой связью со своим хранилищем также поддержана.
   Выдели одну нужную плиту и нажми **QMonitoring → Diagnostics → Plan Preview**.
3. Выбери `physical-bar-plan-trial.json`, затем новое имя JSON-отчёта.
   Если отдельно передан `physical-bar-relocation-draft.json`, эту же кнопку
   можно запустить с ним: будут показаны скорректированные поперечные оси.
4. Укажи сдвиг DXF → внутренние координаты Revit в миллиметрах: `X; Y`.
   Для рабочего снимка `122250` проверялось `0; 0`. Для другой модели/связи это
   значение не считается автоматически подтверждённым. Масштаб и поворот
   команда не подбирает. Высота CAD не используется.
5. Подтверди создание **нового графического вида**. Типы арматуры, глубины и
   разрешение заимствовать плиту не спрашиваются. Дождись проверки Solid и
   рисования; в окне прогресса можно отменить запуск без сохранения части вида.
6. Новый вид откроется автоматически. Можно приближать и рассматривать его
   обычными средствами Revit. Пришли скриншот и сохранённый JSON-отчёт.

## Что означают цвета

- **Синий:** пройдена только консервативная проверка XY относительно этой плиты;
  это не инженерный допуск.
- **Красный:** ось с телом стержня и боковым защитным слоем не помещается в
  общий контур всей толщины плиты; возможны край, проём или высотный уступ.
- **Оранжевый:** нативная проверка Solid для стержня не завершилась. Это не pass.
- **Фиолетовый:** известное пересечение дополнительных стержней одного направления.
  При одновременном конфликте с host приоритет отображения — красный/оранжевый;
  число нерешённых пар остаётся в общей подписи.
- **Бирюзовый:** сдвинутая ось из черновика обхода отверстий, если текущая
  геометрическая проверка host пройдена и нет известного пересечения.
- **Серый:** проекция всех рёбер фактического Solid, а не один горизонтальный разрез.
  Дуговые рёбра представлены аппроксимацией Revit и отмечаются в JSON.

Прямоугольные рамки сертификатов спроса не выдаются за настоящие границы
`LayoutZone` и по умолчанию не рисуются. Число исходных зон в подписи отдельно
от физических стержней и типоразмеров. Расчётная масса не означает, что столько
арматуры установлено в модели. Стержни четырёх направлений разнесены в четыре
панели только на чертеже; исходные XY сохраняются в отчёте и входном JSON.

## Что изменится в модели

Только **один новый DraftingView и его собственные DetailCurve/TextNote**.
В названии и на самом виде написано `GRAPHIC PREVIEW / НЕ АРМАТУРА / НЕ ВЫДАЧА`.
Создания Rebar/модельных линий, изменения плиты, фона, существующих видов,
типов, рабочего набора плиты и активного рабочего набора нет.

Обычная файловая локальная совместная модель и detached-копия с сохранёнными
рабочими наборами поддержаны. Прямой запуск в центральной, облачной или
Revit Server-модели пока отклоняется. Заимствование Floor/рабочих наборов,
Save, Sync и Relinquish команда **не вызывает**. Но новый вид остаётся в
локальном документе и может попасть в центральную модель при последующей
**ручной** синхронизации. Это явно показано перед подтверждением.

После Commit все графические оси считываются обратно: число, принадлежность
новому виду и координаты концов. При ошибке, предупреждении Revit, отмене или
расхождении readback откатывается вся операция, включая уже созданный вид.
Для этого одна транзакция обёрнута в TransactionGroup; успешный результат
остаётся одной операцией Undo. Повторный запуск создаёт новый вид, не заменяет
предыдущий. Удалить результат можно Undo или удалением только этого нового вида.

Если JSON сообщает `rollback_unconfirmed`, откат не доказан: не сохраняй и
не синхронизируй эту копию до проверки; пришли отчёт и текст ошибки.

## Границы проверки

Сравнивается консервативная прямоугольная оболочка XY на всю толщину настоящего
Solid. Боковой защитный слой учитывается по концам, поперёк — ещё и радиус
стержня. Не выбираются фактические высоты; на уступах проверка может быть
строже размещения на отдельно подтверждённом Z. Это не замена физической
проверки покрытия, анкеровки, фоновой арматуры, X/Y-слоёв и 3D-коллизий.

Для нового relocation draft используется **отдельный графический адаптер**:
он проверяет полноту исходных владельцев, массу, количества, диаметры/класс,
продольные 40d и соответствие подписанных сдвигов новым осям. Он не подделывает
старый сертификат неизменных поперечных координат и не разрешает структурный
экспорт. Исходные зоны сохраняются. Геометрия host считывается заново в Revit.

Локальные тесты проверяют Python-логику и API doubles. Реальный отчёт 0.1.0
`qmonitoring-plan-preview-20260914-162843-904000.json` подтвердил чтение плиты,
902 проверки Solid (405 outside / 497 contained / 0 unknown), создание нового
DraftingView и откат после ошибки Python; итоговый вид не остался в документе.
Затем получен настоящий отчёт **0.1.1**
`qmonitoring-plan-preview-20260914-173633-796000.json`: статус
`graphic_preview_created`, Commit, новый вид 13809056; обратно считаны все
902 графические оси с допуском 0,01 мм, статус `matches`. Конструктивных Rebar
создано **0**. Это подтверждает графический просмотр прежней партии, а не
размещение новых исследовательских результатов или прохождение их границ.
