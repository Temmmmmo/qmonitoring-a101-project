# QMonitoring Workflow 8.1 — исходные параметрические зоны

Версия 0.1.3. Revit 2024 / pyRevit IronPython 2.7. **Первый запуск в настоящем
Revit ещё не проверен.** Это отдельная команда: Plan Preview 0.2.3 и
другие кнопки не заменяются. Здесь создаются экземпляры семейств элементов узлов
и типовых аннотаций на текущем плане, либо четыре отдельных чертёжных вида
с цветными изополями и зонами — не физический Rebar и не новая обрезанная партия.

## Установка

Распакуй ZIP в отдельную папку. В pyRevit → Settings → Custom Extension Directories
добавь **родительскую папку**, внутри которой лежит `QMonitoringWorkflow.extension`.
Старые пути не удаляй. Reload pyRevit. Новая вкладка — **QMonitoringWorkflow**,
кнопка «Доп. поля / Workflow 8.1».

## Первый запуск

1. Открой локальную рабочую модель и целевой горизонтальный план. Рабочие наборы
   сохраняются; напрямую центральный файл, cloud/server и 3D-вид пока не поддержаны.
2. Подгрузи DXF или PNG на вид штатными средствами Revit, проверь единицы и оси.
   Для размещения исходных зон поддержана явная трансляция XY при масштабе 1:1
   и одинаковых глобальных осях. Поворот/масштаб не угадываются по картинке.
3. Нажми кнопку и выбери одно из действий:
   - **Сформировать Доп. Поля** — новый расчёт DXF.
   - **Разместить готовые ИСХОДНЫЕ зоны семействами** — на текущем плане.
   - **Создать 4 видов** — четыре отдельных чертёжных вида с цветными изополями
     и прямоугольниками зон, по одному на каждое направление (НИЗ X, НИЗ Y,
     ВЕРХ X, ВЕРХ Y). Выбирается JSON `source-isofields-zones/v1`.
   - **Настроить и сохранить запрос НОВОГО расчёта**.
4. Для режима «Создать 4 видов» выбери JSON с изополями и зонами, укажи смещение
   XY и имя отчёта. Создаются четыре `ViewDrafting` вида с `FilledRegion` по каждому
   КЭ (цвет по уровню шкалы) и `DetailCurve` для `demand_bbox` и осевых огибающих.
    Пост-Commit readback проверяет все виды, цвета и геометрию; ошибка откатывает группу.
5. Для размещения зон семействами загрузите через Revit подходящее семейство
   **элементов узлов** для зоны и **типовых аннотаций** для подписи. В материалах есть
   RVT-шаблон, но нет отдельных RFA с подтверждёнными именами параметров; программа
   не придумывает этот договор.
6. Для нового расчёта выбери исходный DXF, SHK либо явный mapping, фон D/шаг,
   анкеровку ≥40d, ширину 2 или 3 КЭ, алгоритм и предпочтение. Укажи доверенный
   HTTPS-сервер; HTTP допустим только для localhost. Прочитай имена передаваемых
   файлов и **отдельно согласись на upload**. Без согласия данные не отправятся.
   Сервер выполняет новый анализ, ответ связан SHA с точными запросом и исходными
   байтами. Не отправляй материалы без права передачи. Альтернатива без HTTP —
   выбери скачанный `source-isofields-zones/v1` JSON.
7. Проверь расчёт, гейты, источник и выбери «Разместить исходные зоны семействами»,
   новое имя отчёта и известную XY-привязку. Не выбирай JSON обрезанных физических
   стержней: исходные зоны — другая стадия.
   Введи префиксы имён семейств. Один подходящий тип выбирается автоматически,
   несколько — явно списком, отсутствие — ошибка без подмены типа.
8. Разреши временное создание экземпляра для чтения его параметров. Эта операция
   **откатывается** перед продолжением. Выбери соответствие реальных параметров
   экземпляра: длина, осевая ширина, диаметр, условный шаг, число стержней, ID.
   Для линейного семейства длина определяется линией вставки. У аннотации нужен
   отдельный редактируемый текстовый параметр. Параметры типов не изменяются.
   Служебные и декоративные параметры («Экспорт в IFC», «мод_Диаметр кружка»,
   «мод_До стержня», «мод_До стрелки», «Id», «UniqueId», «IfcGUID») больше **не
   предлагаются**: запись инженерного значения в них перебивает габарит семейства
   или портит данные IFC. Если под поле нет подходящего параметра — добавь его
   в семейство, а не занимай чужой.
8a. Для проверенного семейства `ЭУ_Зона доп.армирования : Один стержень с зоной`
   предлагается профиль `eu-zone-one-bar-v1`: пишутся только габариты А/Б, диаметр
   стержней и «Комментарии». Условный шаг и число стержней остаются в тексте
   аннотации и в JSON-отчёте — в семейство они не пишутся.
8b. Дальше выполняется **пробная запись на одном временном экземпляре**: значения
   пишутся, вызывается Regenerate, значения читаются обратно, экземпляр
   откатывается. Если семейство «уводит» габарит формулой или связью, ты увидишь
   это здесь — на одном элементе, а не после отката всей партии. Результат пробы
   попадает в отчёт (`bindings.<роль>.probe`).
9. Подтверди договор семейства: точка вставки — центр осевого прямоугольника,
   локальная X — вдоль стержней. Ширина — расстояние крайних осей, **не AreaBoundary**.
   Для линейного семейства линия идёт между концами по середине осевой ширины.
10. Прочитай итоговое подтверждение. Создаются два экземпляра на каждый исходный
   компонент: зона и аннотация. Проверь внешний вид и пришли сохранённый JSON.

Неравномерная схема шага не становится равномерной: в подписи шаг назван условным,
полные исходные оси/параметры сохранены в отчёте. Само семейство и его формулы
нужно визуально проверить — чтение параметров не доказывает правильность его рисунка.

## Границы нового расчёта

HTTPS-запрос действительно вызывает серверный анализ одного DXF/направления,
но не отменяет `fail`/`not_checked` по покрытию, 40d, раскрою и host. PNG не
оцифровывается, масштаб/поворот и 3D-геометрия семейства не измеряются.
Текущие экземпляры — только элементы узлов/аннотации **на виде**, не Rebar.
Полный шаг 8–9 ТЗ и живой Revit-run не подтверждены.

## Безопасность и проверка

После Commit повторно считываются все новые экземпляры: тип/владелец-вида,
координаты/ориентация, полные ID и параметры. Ошибка, отмена или несовпадение
откатывают всю группу. При `rollback_unconfirmed` не сохраняй и не синхронизируй
модель до разбора отчёта. Плагин не вызывает Checkout, Save, Sync, не переключает
рабочие наборы. Revit может автоматически заимствовать связанные с видом элементы;
откат локальной транзакции не обещает восстановления центральных прав.

Успех означает только создание **исходных параметрических семейств на виде**.
Не подтверждены физическое армирование, его покрытие, коллизии, раскрой или полный
workflow в настоящем Revit. `placement_eligible=false` сохраняется.
