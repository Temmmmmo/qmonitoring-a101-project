# QMonitoring Workflow 8.1 — исходные параметрические зоны

Версия 0.1.0. Revit 2024 / pyRevit IronPython 2.7. **Первый запуск в настоящем
Revit ещё не проверен.** Это отдельная команда: старый Plan Preview 0.2.2 и
другие кнопки не заменяются. Здесь создаются экземпляры семейств элементов узлов
и типовых аннотаций на текущем плане, не физический Rebar и не новая обрезанная партия.

## Установка

Распакуй ZIP в отдельную папку. В pyRevit → Settings → Custom Extension Directories
добавь **родительскую папку**, внутри которой лежит `QMonitoringWorkflow.extension`.
Старые пути не удаляй. Reload pyRevit. Новая вкладка — **QMonitoringWorkflow**,
кнопка «Доп. поля / Workflow 8.1».

## Первый запуск

1. Открой локальную рабочую модель и целевой горизонтальный план. Рабочие наборы
   сохраняются; напрямую центральный файл, cloud/server и 3D-вид пока не поддержаны.
2. Подгрузи DXF или PNG на вид штатными средствами Revit, проверь единицы и оси.
   Для размещения исходных зон поддержана явная трансляция XY при масштабе 1:1
   и одинаковых глобальных осях. Поворот/масштаб не угадываются по картинке.
3. Загрузите через Revit подходящее семейство **элементов узлов** для зоны и
   **типовых аннотаций** для подписи. В материалах есть RVT-шаблон, но нет отдельных
   RFA с подтверждёнными именами параметров; программа не придумывает этот договор.
4. Нажми кнопку, выбери направление и `source-isofields-zones/v1` JSON,
   скачанный из приложения («Исходные изополя и зоны»). Не выбирай JSON обрезанных
   физических стержней: исходные зоны — другая стадия.
5. Выбери «Разместить готовые ИСХОДНЫЕ зоны семействами», новое имя отчёта и XY.
   Введи префиксы имён семейств. Один подходящий тип выбирается автоматически,
   несколько — явно списком, отсутствие — ошибка без подмены типа.
6. Разреши временное создание экземпляра для чтения его параметров. Эта операция
   **откатывается** перед продолжением. Выбери соответствие реальных параметров
   экземпляра: длина, осевая ширина, диаметр, условный шаг, число стержней, ID.
   Для линейного семейства длина определяется линией вставки. У аннотации нужен
   отдельный редактируемый текстовый параметр. Параметры типов не изменяются.
7. Подтверди договор семейства: точка вставки — центр осевого прямоугольника,
   локальная X — вдоль стержней. Ширина — расстояние крайних осей, **не AreaBoundary**.
   Для линейного семейства линия идёт между концами по середине осевой ширины.
8. Прочитай итоговое подтверждение. Создаются два экземпляра на каждый исходный
   компонент: зона и аннотация. Проверь внешний вид и пришли сохранённый JSON.

Неравномерная схема шага не становится равномерной: в подписи шаг назван условным,
полные исходные оси/параметры сохранены в отчёте. Само семейство и его формулы
нужно визуально проверить — чтение параметров не доказывает правильность его рисунка.

## Параметры нового расчёта

Отдельный пункт «Настроить и сохранить запрос НОВОГО расчёта» сохраняет фон D/шаг,
анкеровку ≥40d, минимальную ширину 2 или 3 КЭ, алгоритм и предпочтение массы/числа
стержней. В этой версии он **не запускает алгоритм** и не меняет старые зоны.
PNG не оцифровывается. Полный шаг 8–9 ТЗ пока не закрыт; HTTP-связь с новым
расчётом — следующий срез, а не скрытая имитация уже работающего функционала.

## Безопасность и проверка

После Commit повторно считываются все новые экземпляры: тип/владелец-вида,
координаты/ориентация, полные ID и параметры. Ошибка, отмена или несовпадение
откатывают всю группу. При `rollback_unconfirmed` не сохраняй и не синхронизируй
модель до разбора отчёта. Плагин не вызывает Checkout, Save, Sync, не переключает
рабочие наборы. Revit может автоматически заимствовать связанные с видом элементы;
откат локальной транзакции не обещает восстановления центральных прав.

Успех означает только создание **исходных параметрических семейств на виде**.
Не подтверждены физическое армирование, его покрытие, коллизии, раскрой или полный
workflow в настоящем Revit. `placement_eligible=false` сохраняется.
